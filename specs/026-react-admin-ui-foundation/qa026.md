# QA026: React Admin UI Foundation

## Goal

Validate that the new React admin foundation can be served from `/admin/app`
without weakening the existing FastAPI admin authorization, tenant isolation,
safe bootstrap payloads, Jinja fallbacks, or asset failure behavior.

This QA pass proves that the browser receives only backend-authorized metadata.

It also proves that the existing server-rendered admin console remains the
source of truth for domain pages while later React migration specs are still
disabled.

## What This Guide Covers

- Dedicated local setup for `multi_agent_platform_qa026`.
- React admin build assets under `/admin/static/react`.
- FastAPI routes under `/admin/app`.
- Safe bootstrap metadata for local-principal administrators.
- Auth0-shaped principal coverage through automated route tests.
- Unauthorized, non-admin, and cross-tenant denied behavior.
- Safe manifest summaries that do not expose filesystem paths.
- Disabled future React routes that point reviewers back to existing Jinja pages.
- Frontend type, unit, and build validation.
- Full backend quality gates and coverage.

## How To Use This Guide

Run commands from the repository root.

Keep a terminal open for the API process.

Keep a second terminal open for optional worker checks.

Use the exact QA environment file named `.env.qa026`.

Save command output under `/tmp/qa026-*` when a command below asks for evidence.

Review `qa026_ui.md` after the API checks if you need browser screenshots.

Do not use real Auth0, provider, Telegram, or connector credentials.

Do not change existing Jinja admin routes while validating QA026.

## Environment

Prepare the local environment.

```bash
test ! -f .env || test -f .env.autopilot-backup || cp .env .env.autopilot-backup
cp specs/026-react-admin-ui-foundation/.env.qa026 .env
uv sync
docker compose up -d postgres
docker compose exec -T postgres sh -c 'dropdb -U postgres --if-exists multi_agent_platform_qa026 && createdb -U postgres multi_agent_platform_qa026'
uv run alembic upgrade head

```

Expected:

- The file `.env` contains the QA026 settings.
- The database `multi_agent_platform_qa026` exists.
- Alembic applies all migrations through the current head.
- Artifact directories exist locally.

- The Globex tenant exists with id `22222222-2222-2222-2222-222222222222`.

## Troubleshooting

If `/admin/app` returns `401`, confirm `AUTH_MODE=local_principal` and send `X-Local-Principal`.

If `/admin/app` returns `403`, confirm the principal has an admin role.

If Acme cannot load with `tenant_id`, confirm the Acme tenant seed row exists.

If the React page shows missing assets, run `cd frontend/admin && npm run build`.

If `npm run typecheck` cannot find Node types, run `cd frontend/admin && npm install`.

If `run_playwright_ui.py` cannot log in, confirm the local login page lists `tenant-admin-acme`.

If the worker exits during QA026, continue the React shell checks because the worker is not required for this feature.

If the manifest missing check fails after moving a file, restore `src/multi_agent_platform/web_admin/static/react/manifest.json` and rebuild.

If full coverage fails on unrelated suites, keep the focused QA026 evidence and record the failing suite in reviewer notes before continuing repair.
