# QA048 Live Data Inventory And Mock Guardrails Guide

## Goal

Prove qa048 establishes the live-data cleanup inventory and mock-data guardrails for the React admin platform before Specs 049 through 058 replace the mapped legacy fixtures.

This guide proves four outcomes.

- Current mock-data markers are inventoried, classified, and mapped to a replacement spec.
- New unallowlisted mock markers become blocking findings.
- The React migration dashboard renders the inventory from backend-owned JSON contracts.
- QA evidence stays redaction-safe while preserving enough detail for reviewers.

The expected state after qa048 is warning, not ready. Existing mapped findings are allowed to remain only because every finding is assigned to a later removal spec.

## What This Guide Covers

- Live-data scanner coverage for backend source, frontend source, generated contracts, and built React assets.
- A narrow computed-metadata allowlist for scanner-derived counts.
- Route-target coverage for static `/admin/app` JSON and mutation endpoints.
- Backend route coverage for `/admin/app/migration/live-data-inventory.json`.
- Migration dashboard payload coverage for `live_data_inventory`.
- React client, generated TypeScript contracts, migration panel rendering, and safe fallback behavior.
- QA environment isolation for `multi_agent_platform_qa048`.
- Browser-first evidence for the migration hardening workspace.
- Post-UI API and database checks that prove the UI reflected backend-owned state.
- Multi-agent curl regression coverage after the spec QA flow.

## Troubleshooting

- If the live-data endpoint returns 403, verify the local principal header and tenant query parameters.
- If the scanner reports new regressions, inspect the source path and either remove the marker or map it to the correct later spec.
- If generated contracts are stale, run `uv run python scripts/frontend/generate_admin_react_types.py` and review the generated diff.
- If frontend tests fail on repeated text, prefer role or heading queries before broad text queries.
- If Playwright cannot load the app, verify the qa048 env file was copied and the local app processes started.
- If the curl regression fails, stop the autopilot after one focused repair attempt and record the first failing curl command.
- If evidence contains unsafe text, regenerate it from the safe summary endpoint rather than copying internal logs.
- If route-target coverage reports a gap, add a `LiveDataRouteTarget` or document why the parameterized detail route is deferred.
