# QA030 API And Database Guide

## Goal

QA030 proves that the React workflow builder is safe, scoped, typed, and useful for guided workflow drafting.

The route under review is `/admin/app/workflows`.

The primary builder contract is `/admin/app/workflows/builder.json`.

The lookup contract is `/admin/app/workflows/lookups.json`.

The mutation contracts are `/admin/app/workflows/drafts/{workflow_draft_id}/save`, `/validate`, and `/publish`.

The backend owns draft state, reference choices, graph preview data, validation findings, publish readiness, evidence, revisions, and JSON preview summaries.

React renders generated TypeScript contracts and does not invent workflow, validation, publish, evidence, or revision state.

The feature must not call live model providers.

The feature must not call Telegram.

The feature must not call external connector tools.

Expected: every QA030 value is deterministic, local, and safe to repeat.

What this proves: reviewers can validate workflow authoring without production data.

## What This Guide Covers

- Local QA030 environment setup.
- React admin asset build.
- Protected workflow builder shell checks.
- Platform and tenant builder envelope checks.
- Reference catalog checks.
- Save, stale revision, validation, and publish mutation checks.
- Graph preview and keyboard-readable list checks.
- Redaction, artifact reference, and cross-tenant checks.
- Generated TypeScript contract drift checks.
- Backend, frontend, and full repository quality gates.
- Evidence under `/tmp/qa030-*`.

## How To Use This Guide

Run commands from the repository root.

When a command writes a `/tmp/qa030-*` file, keep it until reviewer notes are complete.

Use `qa030_ui.md` for the browser walkthrough.

Use `qa030_user_guide.md` for a plain-language manual review script.

Do not use production credentials.

Do not connect to live providers.

Do not call Telegram.

Do not call external tools.

Do not paste private prompts, completions, memory contents, channel messages, provider responses, Telegram updates, connector outputs, stack traces, local paths, or tenant data from another organization into any QA note.

Expected: all command output is local and deterministic.

What this proves: the builder can be reviewed safely by developers and QA reviewers.

## Environment

Copy the QA030 environment:

```bash
cp specs/030-react-workflow-builder/.env.qa030 .env
```

Expected: `.env` references `multi_agent_platform_qa030`.

Expected: `.env` references `.data/qa030-artifacts`.

Expected: `.env` references only `qa030/` fake secret references.

Install Python dependencies:

```bash
uv sync
```

Build React admin assets:

```bash
cd frontend/admin
npm install
npm run build
cd ../..
```

Expected: Vite writes `src/multi_agent_platform/web_admin/static/react/manifest.json`.

Reset the QA database:

```bash
docker compose up -d postgres
docker compose exec -T postgres sh -c 'dropdb -U postgres --if-exists multi_agent_platform_qa030 && createdb -U postgres multi_agent_platform_qa030'
uv run alembic upgrade head
```

Seed local tenants:

```bash
docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa030 -v ON_ERROR_STOP=1 -c "INSERT INTO tenants (tenant_id, slug, display_name, status, created_at, updated_at) VALUES ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP), ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP) ON CONFLICT (slug) DO NOTHING"
```

Create evidence directories:

```bash
mkdir -p .data/qa030-artifacts output/playwright/qa030_ui
```

## Troubleshooting

If `/admin/app/workflows` returns 401, confirm `AUTH_MODE=local_principal` and sign in through `/auth/local-login`.

If tenant login fails, confirm Acme and Globex tenant rows were seeded in `multi_agent_platform_qa030`.

If React assets are missing, rerun `cd frontend/admin && npm install && npm run build`.

If generated types drift, rerun `uv run python scripts/frontend/generate_admin_react_types.py`.

If Playwright cannot find publish text, rerun validation from a clean browser session so the local-principal cookie starts from a known state.

Expected: each troubleshooting step uses local deterministic QA030 resources.

What this proves: common failures can be resolved without weakening auth, tenant, or redaction behavior.
