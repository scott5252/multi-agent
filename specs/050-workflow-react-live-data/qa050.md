# QA050: Workflow React Live Data

## Goal

Prove qa050 replaces deterministic workflow React data with live, authorized workflow registry, builder, detail, lookup, version, publish-gate, and durable mutation behavior.

This guide proves six outcomes.

- Workflow registry and create routes return live durable rows or truthful empty states.
- Builder, draft detail, version detail, lookups, and publish-gate routes project stored workflow data or safe unavailable states.
- Create, save, validate, restore, copy, and publish actions call durable workflow services instead of returning fake success.
- Tenant authorization fails closed for cross-tenant workflow identifiers.
- Generated TypeScript contracts accept live empty-state workflow envelopes and reject malformed data.
- The live-data scanner tracks retired Spec 030 deterministic markers such as `DEFAULT_DRAFT_ID`, `DEFAULT_LINEAGE_ID`, `draft-rev-qa030`, fake graph nodes, fake publish evidence, and fake audit references.

## What This Guide Covers

- QA environment setup for `multi_agent_platform_qa050`.
- Empty database workflow registry and builder checks.
- Seeded workflow route, detail, validation, and publish-gate checks.
- Durable workflow mutation tests for create, save, validate, restore, copy, and publish.
- Generated TypeScript contract checks for nullable workflow builder state.
- Frontend workflow typecheck, tests, and production build.
- Spec QA, Playwright UI, post-UI API evidence, and curl regression validation.
- Redaction expectations for workflow graph, prompts, memory, credentials, provider payloads, and tool payloads.

## Troubleshooting

- If `/admin/app/workflows/builder.json` reports unavailable state, confirm migrations ran against `multi_agent_platform_qa050` and the local principal has tenant access.
- If the UI still shows `qa030`, rebuild `frontend/admin` and confirm FastAPI serves the updated manifest.
- If Playwright cannot click the local login button, confirm the `tenant-admin-acme` local principal exists in `.env.qa050`.
- If workflow mutation tests fail with stale revisions, rerun the focused test from a clean qa050 database.
- If curl regression fails, inspect `.data/curl_test_runs/qa050-after-spec` and keep the active spec blocked until the regression is repaired.
- If redaction evidence contains raw prompt, memory, credential, provider, or tool payload text, stop and fix the serializer before continuing.

Expected: troubleshooting notes identify the failing layer without exposing sensitive payloads.

What this proves: reviewers have safe recovery steps for common qa050 failures.
