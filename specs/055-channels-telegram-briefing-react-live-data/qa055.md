# QA055 Guide: Channels Telegram Briefing React Live Data

## Goal

Prove qa055 replaces deterministic channel, Telegram, and briefing React
payloads with live repository-backed configuration, alias, identity, delivery,
webhook receipt, workflow run, briefing preference, and audit evidence.

Expected: an empty tenant shows a truthful empty channel state.

Expected: a seeded tenant shows only persisted Acme channel rows.

Expected: the React page can save briefing preferences through the backend.

Expected: the database shows a second briefing preference revision after the
browser action.

Expected: no bot token, webhook secret, full Telegram identifier, raw message,
raw preference, raw run payload, provider token, credential value, local path,
or unauthorized tenant label is rendered.

What this proves: qa055 removes the fixed QA036 channel and briefing data path
instead of moving deterministic rows into another production helper.

## What This Guide Covers

This guide covers the local QA environment for `multi_agent_platform_qa055`.

It validates these React channel and briefing routes:

- `/admin/app/channels`
- `/admin/app/channels/bootstrap.json`
- `/admin/app/channels/telegram/deliveries.json`
- `/admin/app/channels/telegram/link-tokens`
- `/admin/app/channels/briefing/preferences.json`
- `/admin/app/channels/briefing/preferences`

Expected: each JSON route can show live data or an explicit empty state.

Expected: Acme can see the QA055 seeded Telegram and briefing records.

Expected: Globex sees an empty state and cannot see Acme rows.

Expected: delivery diagnostics are derived from persisted delivery attempts.

Expected: workflow run links are derived from persisted runtime run rows.

Expected: briefing preference summaries expose safe counts and labels only.

What this proves: the live-data replacement includes route behavior, tenant
isolation, redaction, run evidence, delivery evidence, and a persisted browser
action.

Copy the QA environment.

```bash
cp specs/055-channels-telegram-briefing-react-live-data/.env.qa055 .env
```

Expected: `.env` contains `APP_NAME=multi-agent-platform-qa055`.

Install dependencies.

```bash
uv sync
```

Expected: dependencies install without changing production configuration.

Start PostgreSQL.

```bash
docker compose up -d postgres
```

Expected: the local PostgreSQL container is running.

Reset only the qa055 database.

```bash
docker compose exec -T postgres sh -c 'dropdb -U postgres --if-exists multi_agent_platform_qa055 && createdb -U postgres multi_agent_platform_qa055'
```

Expected: only `multi_agent_platform_qa055` is dropped and recreated.

Run migrations.

```bash
uv run alembic upgrade head
```

Expected: Alembic reaches the latest revision.

Seed local tenants.

```bash
docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa055 -v ON_ERROR_STOP=1 -c "INSERT INTO tenants (tenant_id, slug, display_name, status, created_at, updated_at) VALUES ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP), ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP) ON CONFLICT (slug) DO NOTHING"
```

Expected: Acme and Globex tenant rows exist.

Seed qa055 channel, Telegram, run, and briefing records.

```bash
uv run python scripts/qa/seed_channels_briefing_qa055.py
```

Expected: the command prints `Seeded QA055 channel Telegram briefing live records`.

Create artifact directories.

```bash
mkdir -p .data/qa055-artifacts output/playwright/qa055_ui
```

Expected: QA artifact directories exist.

Start the app.

```bash
uv run uvicorn multi_agent_platform.api.main:app --host 127.0.0.1 --port 8000
```

Expected: the API is reachable on `http://127.0.0.1:8000`.

## Troubleshooting

If the app cannot connect to the database, recopy `.env.qa055` to `.env` and
confirm `DATABASE_URL` uses `multi_agent_platform_qa055`.

If the channel page is empty for Acme, rerun `uv run python scripts/qa/seed_channels_briefing_qa055.py`.

If the webhook is not ready, confirm `TELEGRAM_PROVIDER_TOKEN_REF` and
`TELEGRAM_WEBHOOK_SECRET` use safe qa055 static references.

If Playwright cannot find `Save Preferences`, sign in as `tenant-user-acme`
instead of the tenant admin principal.

If post-UI verification fails on revision count, rerun the Playwright command
and confirm the page showed `Preference profile saved with redacted summaries.`.

Expected: focused repair should stay inside the qa055 spec surface.

Expected: unrelated dirty worktree changes should remain untouched.

What this proves: repair work is scoped and respects the autopilot rules.
