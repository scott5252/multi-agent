# QA065 Guide: Agent Communication Graph Contracts And Projections

## Goal

Validate that Spec 065 exposes backend-owned Agent Communication Graph JSON
contracts for workflow drafts and published workflow bundles without adding
production sample graph records, leaking unsafe text, or bypassing workflow
authorization.

## What This Guide Covers

This guide covers the backend API contract, deterministic local-principal QA
setup, draft graph projection, published version graph projection, empty graph
state, cross-tenant denial, generated TypeScript freshness, redaction checks,
and required repository quality gates for qa065.

It does not cover React graph canvas rendering. That begins in Spec 066. It
does not cover runtime run graph overlays. That begins in Spec 067. It does not
add durable interaction evidence. That decision is deferred to Spec 068.

## How To Use This Guide

Run the commands in order from the repository root. Save command output under
`/tmp/qa065-*` so a reviewer can inspect the evidence without reading terminal
scrollback.

What this proves: the feature is a safe backend projection over durable workflow
records, not a UI mock or a synthetic graph data source.

## Published Graph Verification

Validate and publish the same workflow.

```bash
curl -sS -X POST -H "$ACME_HEADER" \
  "$BASE_URL/admin/workflows/drafts/$QA065_DRAFT_ID/validate" \
  | tee /tmp/qa065-validation.json
export QA065_VALIDATION_ID="$(jq -r '.validation_result_id' /tmp/qa065-validation.json)"
```

Expected: validation status is `passed`.

```bash
curl -sS -X POST -H "$ACME_HEADER" -H "$JSON_HEADER" \
  "$BASE_URL/admin/workflows/drafts/$QA065_DRAFT_ID/publish" \
  -d '{"validation_result_id":"'"$QA065_VALIDATION_ID"'","reason":"QA065 publish"}' \
  | tee /tmp/qa065-publish.json
export QA065_VERSION_ID="$(jq -r '.workflow_version_bundle_id' /tmp/qa065-publish.json)"
```

Expected: a non-null published workflow version bundle ID is returned.

```bash

  "$BASE_URL/admin/workflows/versions/$QA065_VERSION_ID/agent-graph" \
  | tee /tmp/qa065-version-agent-graph.json
jq -e '.source == "published_version" and .partial == false and .provenance.workflow_version_bundle_id == env.QA065_VERSION_ID' /tmp/qa065-version-agent-graph.json
```

Expected: published graph provenance points at the published bundle and the
graph topology is loaded from durable bundle evidence.

## Troubleshooting

- If validation fails with `join_policy.strategy`, use `all_success`, `quorum`, `first_success`, or `manual_resolution`.
- If validation fails with `approval_gate.approver_scope`, use `tenant_admin`, `platform_admin`, or `named_role`.
- If publish returns `409`, inspect `/tmp/qa065-validation.json` and confirm there are zero blocking findings.
- If the version graph is partial, inspect the filesystem storage root and confirm the compiled bundle artifact exists.
- If generated TypeScript is stale, run `uv run python scripts/frontend/generate_admin_react_types.py` and review the generated diff.
- If cross-tenant denial leaks tenant names, stop and fix the workflow visibility path before continuing.
- If unsafe text appears in graph JSON, check `safe_agent_graph_text` validators and source workflow labels.
- If Playwright cannot start the API, ensure port `8000` is free and `.env.qa065` is copied to `.env`.
- If curl regression fails, inspect the first failing command in the generated curl-test output directory.
- If Docker is not ready, start Docker Desktop and rerun `docker compose up -d postgres`.
