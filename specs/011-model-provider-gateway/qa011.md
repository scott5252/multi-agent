# QA011: Model Provider Gateway

## Goal

Validate that Spec `011` delivers model provider connection management,
safe provider testing, catalog publication evidence, and runtime gateway
metadata without exposing credentials, prompts, completions, provider tokens, or
local endpoint secrets.

This guide is written for a reviewer who wants deterministic copy/paste steps.
It covers the backend, the shared admin shell Web UI, API behavior, database
evidence, redaction checks, and automated quality gates.

## What This Guide Covers

- Dedicated PostgreSQL database: `multi_agent_platform_qa011`.
- Local-principal auth for platform admin, Acme tenant admin, Globex tenant
  admin, and Acme operator.
- Deterministic Acme and Globex tenants.
- `/admin/model-providers` list, create, detail, edit, test, and catalog pages.
- OpenAI and local OpenAI-compatible provider metadata.
- Local endpoint allowlist settings for schemes, hosts, ports, and CIDRs.
- Secret-reference-only credential handling.
- Safe probe result storage with health state derivation.
- Catalog sync evidence for healthy and unavailable provider entries.
- Tenant-scoped read visibility and platform-admin-only mutation.
- Runtime gateway attempt metadata shape.
- Redaction scans across tables, docs, and logs.
- Required automated evidence: Ruff, format, mypy, focused tests, full coverage,
  migration upgrade, and QA document validation.

Current implementation notes:

- The admin experience is server-rendered and works without optional
  JavaScript.
- `model_providers.js` only enhances model row editing and async test/sync
  actions.
- Local provider URLs with userinfo or secret-like query parameters must be
  rejected before outbound calls.
- Stored diagnostic summaries are intentionally terse; raw provider responses
  are not review evidence.

## How To Use This Guide

Use two terminal windows from the repository root.

- Terminal A runs the API.
- Terminal B runs setup, `curl`, SQL, redaction scans, and quality commands.

Keep Terminal B open because it stores shared variables and writes evidence
files under `/tmp/qa011-*`.

If a command returns the wrong HTTP status, inspect the saved `/tmp/qa011-*`
file before continuing. The expected status and evidence are named after every
command.

## Environment

1. Copy the QA011 environment file:

   ```bash
   cp specs/011-model-provider-gateway/.env.qa011 .env
   ```

   Expected: no output.

   What this proves: the app is configured for local-principal auth, fake QA011
   secret references, the dedicated `multi_agent_platform_qa011` database, and
   `.data/qa011-artifacts` storage.

2. Confirm command-line tools:

   ```bash
   curl --version | head -1
   jq --version
   ```

   Expected: both commands print versions.

   What this proves: the reviewer can capture HTTP and JSON evidence.

3. Remove old evidence files:

   ```bash
   find /tmp -type f \( -name 'qa011-*.html' -o -name 'qa011-*.json' -o -name 'qa011-*.txt' \) -exec rm -f {} +
   ```

   Expected: no output.

4. Install dependencies:

   ```bash
   uv sync
   ```

   Expected: dependencies install or are already synchronized.

5. Start PostgreSQL:

   ```bash
   docker compose up -d postgres
   ```

   Expected: the PostgreSQL service is running.

6. Create the dedicated QA database:

   ```bash
   docker compose exec -T postgres sh -c \
     'psql -U postgres -d postgres -tc "SELECT 1 FROM pg_database WHERE datname = '\''multi_agent_platform_qa011'\''" | grep -q 1 || createdb -U postgres multi_agent_platform_qa011'
   ```

   Expected: no output.

7. Apply migrations:

   ```bash
   uv run alembic upgrade head
   ```

   Expected: migration `0011_model_provider_gateway` is applied.

8. Seed deterministic tenants and clear QA011 provider evidence:

   ```bash
   docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa011 -v ON_ERROR_STOP=1 <<'SQL'
   INSERT INTO tenants (
     tenant_id, slug, display_name, status, created_at, updated_at
   ) VALUES
     ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP),
     ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP)
   ON CONFLICT (tenant_id) DO UPDATE SET
     slug = EXCLUDED.slug,
     display_name = EXCLUDED.display_name,
     status = EXCLUDED.status,
     updated_at = CURRENT_TIMESTAMP;

   DELETE FROM gateway_invocation_attempts;
   DELETE FROM catalog_sync_records;
   DELETE FROM connection_health_snapshots;
   DELETE FROM connection_test_results;
   DELETE FROM connection_tenant_visibility;
   DELETE FROM provider_model_definitions;
   DELETE FROM model_provider_connections;
   SQL
   ```

   Expected: SQL completes without errors.

## API Connection Creation

Create an OpenAI provider connection:

```bash
curl -sS -X POST "$QA011_BASE_URL/admin/model-providers/api/connections" \
  -H "$QA011_PLATFORM_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{
    "provider_type": "openai",
    "display_name": "QA011 OpenAI",
    "timeout_policy": {"connect_seconds": 5, "read_seconds": 30, "total_seconds": 45},
    "visibility": {"mode": "platform_default", "tenant_ids": []},
    "models": [{"model_id": "gpt-qa011", "display_name": "GPT QA011"}],
    "credential_secret_reference_ids": ["qa011/openai-placeholder"],
    "active": true
  }' | tee /tmp/qa011-openai-create.json
```

Expected: JSON includes `provider_connection_id`, `provider_type` `openai`,
`health_state`, model metadata, and secret reference ids only.

Create a local OpenAI-compatible connection:

```bash
curl -sS -X POST "$QA011_BASE_URL/admin/model-providers/api/connections" \
  -H "$QA011_PLATFORM_HEADER" \
  -H 'Content-Type: application/json' \
  -d "{
    \"provider_type\": \"local_openai_compatible\",
    \"display_name\": \"QA011 Local\",
    \"base_url\": \"http://127.0.0.1:11434\",
    \"timeout_policy\": {\"connect_seconds\": 5, \"read_seconds\": 30, \"total_seconds\": 45},
    \"visibility\": {\"mode\": \"tenant_allowlist\", \"tenant_ids\": [\"$QA011_ACME_TENANT\"]},
    \"models\": [{\"model_id\": \"local-qa011\", \"display_name\": \"Local QA011\"}],
    \"credential_secret_reference_ids\": [\"qa011/local-placeholder\"],
    \"active\": true
  }" | tee /tmp/qa011-local-create.json
```

Expected: JSON includes `local_openai_compatible`, safe base URL, Acme
visibility, and no credential values.

What this proves: platform-admin create flows persist safe metadata and tenant
visibility.

## Negative Authorization Checks

Try to create as a tenant admin:

```bash
curl -sS -o /tmp/qa011-tenant-create-denied.json -w '%{http_code}\n' \
  -X POST "$QA011_BASE_URL/admin/model-providers/api/connections" \
  -H "$QA011_TENANT_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"provider_type":"openai","display_name":"Denied","models":[{"model_id":"denied"}],"credential_secret_reference_ids":["qa011/openai-placeholder"]}'
```

Expected: HTTP status is `403` or `422`; no new tenant-created connection is
stored.

Try an unsafe local URL:

```bash
curl -sS -o /tmp/qa011-unsafe-local.json -w '%{http_code}\n' \
  -X POST "$QA011_BASE_URL/admin/model-providers/api/connections" \
  -H "$QA011_PLATFORM_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"provider_type":"local_openai_compatible","display_name":"Unsafe","base_url":"http://user:pass@192.0.2.10:9999/v1?token=value","models":[{"model_id":"unsafe"}],"credential_secret_reference_ids":["qa011/local-placeholder"]}'
```

Expected: HTTP status is `422`.

What this proves: mutation is platform-admin-only and local endpoint validation
fails closed before probes.

## Troubleshooting

- If `/admin/model-providers` returns 401, confirm the
  `X-Local-Principal` header matches `.env.qa011`.
- If the platform admin cannot see the nav item, confirm the route surface
  policy for `GET:/admin/model-providers` is loaded and the app was restarted.
- If local provider creation fails unexpectedly, inspect
  `MODEL_PROVIDER_LOCAL_ALLOWED_HOSTS` and
  `MODEL_PROVIDER_LOCAL_ALLOWED_PORTS`.
- If migration fails because columns already exist, drop and recreate
  `multi_agent_platform_qa011`, then rerun `uv run alembic upgrade head`.
- If redaction scans match QA placeholder names, confirm the match is a
  reference id and not a raw credential value.
