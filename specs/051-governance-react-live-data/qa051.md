# QA051: Governance React Live Data

## Goal

Prove qa051 replaces deterministic governance React payloads with live repository-backed governance data, truthful empty states, and durable safe mutations.

The governance workspace covers provider readiness, credential-reference metadata, prompt versions, prompt previews, runtime profiles, routing preview, policy history, and run provenance.

This guide keeps the review centered on safe summaries.

Raw prompt content must not appear.

Raw completion text must not appear.

Resolved credential values must not appear.

Provider authorization headers must not appear.

Private run payloads must not appear.

Local filesystem paths must not appear in browser or QA artifacts.

Expected: qa051 validation uses only local-principal identities and the isolated `multi_agent_platform_qa051` database.

What this proves: governance pages now describe real stored records, or honestly say that no safe record exists.

## What This Guide Covers

This guide covers the local QA environment for `multi_agent_platform_qa051`.

It covers empty governance bootstrap behavior.

It covers a seeded prompt that exists because a QA setup command wrote it to the database.

It covers a browser-visible prompt save action that creates a new durable draft revision.

It covers API checks for platform, tenant, and cross-tenant governance responses.

It covers schema, route, service, scanner, performance, generated TypeScript, frontend, Playwright, and curl validation.

It covers redaction expectations for prompt previews and credential metadata.

It covers reviewer evidence files under `/tmp/qa051-*`.

It covers the expected limitation that provider probes remain local-safe and do not call a live provider.

Expected: seeded data is created only by `scripts/qa/seed_governance_qa051.py` or automated tests.

What this proves: qa051 does not move fixed governance data into production builders or React fixtures.

## Troubleshooting

If the API cannot connect to the database, verify `.env` was copied from `.env.qa051`.

If migrations fail, recreate only `multi_agent_platform_qa051` and rerun Alembic.

If the seeded prompt is missing, rerun `uv run python scripts/qa/seed_governance_qa051.py`.

If Playwright cannot find `Save summary`, confirm the platform bootstrap route includes `QA051 Governance Prompt`.

If Playwright saves the prompt but verification fails, inspect `/tmp/qa051-api-evidence.txt` and run the database verification again.

If ruff format fails, run the formatter only after confirming no unrelated user edits would be rewritten unexpectedly.

If mypy fails outside touched governance files, capture the failure and decide whether it is an existing dirty-worktree issue or a qa051 regression.

If coverage fails, rerun the focused backend tests first to identify the failing domain.

If a response contains raw prompt text, raw completion text, credential values, authorization headers, or local absolute paths, stop and treat it as a qa051 security blocker.

Expected: troubleshooting steps preserve the dirty worktree and do not require a Git commit.

What this proves: failures can be diagnosed without weakening the live-data or redaction requirements.
