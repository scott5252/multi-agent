# QA006: User Interaction Channels

## Goal

Validate that Web UI, Telegram, and Web API channels all use the same workflow
run interaction model for invocation, status, progress, approvals, results,
terminal notifications, callbacks, and artifact download URLs.

## What This Guide Covers

Use this guide as a standalone reviewer checklist for Spec `006`. It validates:

- Web API invocation, status, timeline, SSE, result, subscription, callback,
  approval, cancellation, artifact list, and artifact URL responses.
- Web UI run start, run detail rendering, support trace visibility, and SSE
  event endpoint behavior.
- Telegram link-token issuance, `/link`, protected commands, unlinked denial,
  provider secret handling, and duplicate `update_id` replay.
- Shared lifecycle names: `queued`, `running`, `waiting-for-input`,
  `completed`, `failed`, and `canceled`.
- Idempotency conflict handling and safe cross-tenant denial.
- QA evidence commands for Ruff, mypy, focused channel tests, and full coverage.

## Web API Smoke Test

Start a run:

```bash
curl -i -X POST http://127.0.0.1:8000/runs \
  -H "Content-Type: application/json" \
  -H "X-Local-Principal: tenant-admin-acme" \
  -H "X-Idempotency-Key: qa006-run-001" \
  -d '{
    "workflow_id": "published-demo-workflow",
    "inputs": {"topic": "qa006"},
    "channel": "web_api"
  }'
```

Expected: `202 Accepted` with `run_id`, `state: "queued"`, `status_url`, and
`trace_id`.

Then verify:

```bash
curl -H "X-Local-Principal: tenant-admin-acme" \
  http://127.0.0.1:8000/runs/RUN_ID/status

curl -H "X-Local-Principal: tenant-admin-acme" \
  "http://127.0.0.1:8000/runs/RUN_ID/timeline?limit=100"

curl -H "X-Local-Principal: tenant-admin-acme" \
  http://127.0.0.1:8000/runs/RUN_ID/result
```

Expected: status uses one of the six shared lifecycle states, timeline includes
`run_queued`, and result clearly reports availability.

## Idempotency And Auth

1. Repeat the original `POST /runs` with the same idempotency key and payload.
   Expected: same `run_id`.
2. Reuse the same key with different input. Expected: `409` and
   `idempotency_conflict`.
3. Request the run as another tenant principal. Expected: safe `404` or
   unauthorized response without protected run details.

Concrete cross-tenant check:

```bash
curl -i -H "X-Local-Principal: tenant-admin-globex" \
  http://127.0.0.1:8000/runs/RUN_ID/status
```

Expected: `404` with `error.category: "invalid_run_id"`.

## Waiting Prompt

Create a local waiting run with:

```bash
curl -X POST http://127.0.0.1:8000/runs \
  -H "Content-Type: application/json" \
  -H "X-Local-Principal: tenant-admin-acme" \
  -H "X-Idempotency-Key: qa006-waiting-001" \
  -d '{
    "workflow_id": "waiting-demo",
    "inputs": {"topic": "approval", "_channel_state": "waiting"},
    "channel": "web_api"
  }'
```

Fetch status and copy `waiting_prompt.prompt_id`, then approve:

```bash
curl -X POST http://127.0.0.1:8000/runs/RUN_ID/approvals/PROMPT_ID/decision \
  -H "Content-Type: application/json" \
  -H "X-Local-Principal: tenant-admin-acme" \
  -H "X-Idempotency-Key: qa006-decision-001" \
  -d '{"action": "approve", "prompt_version": 1, "decision_payload": {}}'
```

Expected: `202`, `accepted: true`, and latest status moves out of
`waiting-for-input`. Repeat with a new idempotency key. Expected: `409`,
`accepted: false`, and latest status returned without mutation.

Cancellation check for an active run:

```bash
curl -X POST http://127.0.0.1:8000/runs/RUN_ID/cancel \
  -H "Content-Type: application/json" \
  -H "X-Local-Principal: tenant-admin-acme" \
  -H "X-Idempotency-Key: qa006-cancel-001" \
  -d '{"reason": "qa requested cancellation"}'
```

Expected: `202` and `state: "canceled"`. Repeating with the same key returns
the same accepted outcome.

## Subscriptions And Callbacks

Subscribe to terminal notifications:

```bash
curl -X POST http://127.0.0.1:8000/runs/RUN_ID/subscriptions \
  -H "Content-Type: application/json" \
  -H "X-Local-Principal: tenant-admin-acme" \
  -H "X-Idempotency-Key: qa006-subscribe-001" \
  -d '{"channel": "web_api", "event_types": ["terminal"]}'
```

Expected: `201` with `status: "active"`.

Register an API callback:

```bash
curl -X POST http://127.0.0.1:8000/runs/RUN_ID/callbacks \
  -H "Content-Type: application/json" \
  -H "X-Local-Principal: tenant-admin-acme" \
  -H "X-Idempotency-Key: qa006-callback-001" \
  -d '{
    "callback_url": "https://example.test/platform-callback",
    "event_types": ["terminal", "waiting_prompt", "artifact_ready"]
  }'
```

Expected: `201` with `status: "active"`. Callback delivery failure must not
change the run lifecycle.

## Troubleshooting

- `401`: include `X-Local-Principal: tenant-admin-acme` or sign in through the
  local login page.
- `404 invalid_run_id`: verify the run id belongs to the same tenant as the
  current principal.
- `409 idempotency_conflict`: use a new idempotency key or repeat the exact
  original payload.
- `409 accepted: false` for a prompt decision: the prompt is stale or already
  answered; fetch latest status.
- Telegram protected command returns `unauthorized`: create a fresh link token
  and send `/link TOKEN` from the same chat/user pair.
- Artifact list is empty: use the completed local run payload with
  `"_channel_state": "completed"` to generate reviewable artifact metadata.

- Idempotency conflict and cross-tenant denial are visible.
- `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`,
