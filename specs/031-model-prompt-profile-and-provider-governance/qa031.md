# QA031 API And Database Guide

## Goal

QA031 proves that the React governance experience is safe, scoped, typed, and useful for non-technical administrators.

The route under review is `/admin/app/governance`.

The primary dashboard contract is `/admin/app/governance/bootstrap.json`.

The provider list contract is `/admin/app/governance/providers.json`.

The prompt list contract is `/admin/app/governance/prompts.json`.

The profile list contract is `/admin/app/governance/profiles.json`.

The history contract is `/admin/app/governance/history.json`.

The run provenance contract is `/admin/app/governance/provenance/run-qa031-briefing.json`.

Provider probe actions post to `/admin/app/governance/providers/{provider_id}/probe`.

Provider credential reference actions post to `/admin/app/governance/providers/{provider_id}/credential-reference`.

Prompt save and preview actions post to protected prompt governance routes.

Profile save and resolution actions post to protected profile governance routes.

Routing preview posts to `/admin/app/governance/routing/preview`.

Expected: platform administrators can run provider probes and change credential references.

Expected: tenant administrators cannot mutate provider configuration.

Expected: tenant administrators can review authorized provider readiness, prompt grants, profile grants, routing previews, policy history, and provenance.

Expected: all governance output is generated by backend contracts and generated TypeScript.

Expected: local validation does not call live model providers.

Expected: local validation does not call Telegram.

Expected: local validation does not call external connector tools.

Expected: local validation does not resolve real credential values.

What this proves: reviewers can validate model, prompt, profile, provider, routing, and provenance governance without exposing sensitive runtime data.

## What This Guide Covers

- Local QA031 environment setup.
- React admin asset build.
- Protected governance shell checks.
- Platform and tenant dashboard envelope checks.
- Provider setup, credential reference, health, probe, and direct-call guardrail checks.
- Prompt version, safe save, and unsafe fixture preview checks.
- Runtime profile save and read-only resolution checks.

- Evidence under `/tmp/qa031-*`.

## How To Use This Guide

Run commands from the repository root.

When a command writes a `/tmp/qa031-*` file, keep it until reviewer notes are complete.

Use `qa031_ui.md` for the browser walkthrough.

Use `qa031_user_guide.md` for a plain-language manual review script.

Do not use real provider credentials.

Do not connect to live providers.

Do not call Telegram.

Do not call external tools.

Do not paste private prompts, completions, memory contents, channel messages, provider responses, connector outputs, stack traces, local paths, or tenant data from another organization into any QA note.

Expected: all command output is local and deterministic.

Expected: governance diagnostics are safe summaries and artifact references.

What this proves: the governance route can be reviewed safely by developers and QA reviewers.

## Troubleshooting

If local login does not show `platform-admin`, check `LOCAL_PRINCIPAL_CATALOG_JSON` in `.env.qa031`.

If provider probe returns 403 for `platform-admin`, confirm the catalog grants `admin:model-providers:write`.

If tenant dashboard returns 403 for Acme, confirm the Acme tenant row exists in `multi_agent_platform_qa031`.

If React assets are missing, rerun `cd frontend/admin && npm install && npm run build`.

If route data looks stale, rebuild assets and restart FastAPI.

If unsafe text appears, stop the review and treat the run as failed.

If cross-tenant output shows `Globex`, stop the review and treat the run as failed.

If full coverage fails, inspect the first failing test before rerunning the whole suite.

Expected: troubleshooting does not require real provider credentials or external services.
