# QA014: Skill Registry And Installation Lifecycle

## Goal

Validate Spec `014` for governed skill package publication, tenant
installation, credential-reference readiness, smoke-test evidence, binding
eligibility, quarantine, redaction, and audit-safe reviewer evidence.

This guide is written for local review. It uses deterministic Acme and Globex
tenants, local-principal authentication, a dedicated PostgreSQL database named
`multi_agent_platform_qa014`, and filesystem artifact storage under
`.data/qa014-artifacts`.

## What This Guide Covers

- Local QA setup for `qa014`.
- Deterministic tenants and local principals.
- Alembic migration coverage for skill lifecycle tables.
- Platform package creation and validation.
- Immutable package version publication.
- Tenant availability grant checks.
- Tenant installation and readiness blocking.
- Credential reference configuration without raw credential values.
- Smoke-test evidence summaries.
- Binding eligibility allow and deny evidence.
- Cross-tenant installation denial.
- Quarantine blocking new installs and runtime use.
- Redaction checks for API responses and logs.
- Required automated evidence and full quality commands.

## How To Use This Guide

Use two terminals from the repository root.

Terminal A runs the API server.

Terminal B runs setup, seed commands, curl checks, SQL checks, and automated
evidence commands.

Keep Terminal B open so shell variables remain available.

Evidence files are written under `/tmp/qa014-*`.

What this proves: the reviewer can repeat the lifecycle from a clean database
and preserve evidence without reading implementation code.

## Manual API Verification

Create the platform package.

```bash
curl -sS -X POST "$BASE_URL/admin/skill-registry/packages" \
  -H "$PLATFORM_HEADER" -H 'Content-Type: application/json' \
  -d '{"slug":"calendar-assistant","display_name":"Calendar Assistant","description":"Safe calendar skill.","owner_principal_id":"platform-admin"}' \
  | tee /tmp/qa014-package.json
```

Expected: JSON contains `"slug":"calendar-assistant"`.

Validate the candidate.

```bash
curl -sS -X POST "$BASE_URL/admin/skill-registry/packages/calendar-assistant/versions/validate" \
  -H "$PLATFORM_HEADER" -H 'Content-Type: application/json' \
  -d @/tmp/qa014-manifest.json | tee /tmp/qa014-validation.json
```

Expected: JSON contains `"status":"passed"` and a `sha256:` manifest digest.

Publish the version.

```bash
curl -sS -X POST "$BASE_URL/admin/skill-registry/packages/calendar-assistant/versions" \
  -H "$PLATFORM_HEADER" -H 'Content-Type: application/json' \
  -d @/tmp/qa014-manifest.json | tee /tmp/qa014-version.json
```

Expected: JSON contains `"semantic_version":"1.2.3"` and
`"validation_status":"passed"`.

Grant Acme availability.

```bash
curl -sS -o /tmp/qa014-grant.txt -w '%{http_code}\n' -X POST \
  "$BASE_URL/admin/skill-registry/packages/calendar-assistant/versions/1.2.3/availability" \
  -H "$PLATFORM_HEADER" -H 'Content-Type: application/json' \
  -d '{"tenant_id":"11111111-1111-1111-1111-111111111111"}'
```

Expected: command prints `204`.

Confirm Acme can discover the version.

```bash
curl -sS "$BASE_URL/admin/skill-registry/tenants/$ACME_TENANT_ID/available-versions" \
  -H "$ACME_HEADER" | tee /tmp/qa014-acme-available.json
```

Expected: JSON includes `calendar-assistant`.

Confirm Globex cannot discover it.

```bash
curl -sS "$BASE_URL/admin/skill-registry/tenants/$GLOBEX_TENANT_ID/available-versions" \
  -H "$GLOBEX_HEADER" | tee /tmp/qa014-globex-available.json
```

Expected: JSON is an empty list.

Install for Acme.

```bash
curl -sS -X POST "$BASE_URL/admin/skill-registry/installations" \
  -H "$ACME_HEADER" -H 'Content-Type: application/json' \
  -d '{"tenant_id":"11111111-1111-1111-1111-111111111111","slug":"calendar-assistant","semantic_version":"1.2.3"}' \
  | tee /tmp/qa014-installation.json
```

Expected: JSON contains `"readiness_state":"blocked"` because credentials
are not configured yet.

Export installation identifiers.

```bash
export QA014_INSTALLATION_ID=$(jq -r '.installation_id' /tmp/qa014-installation.json)
export QA014_REVISION_TOKEN=$(jq -r '.revision_token' /tmp/qa014-installation.json)
```

Expected: no output and both variables are non-empty.

Configure a credential reference.

```bash
curl -sS -X POST "$BASE_URL/admin/skill-registry/installations/$QA014_INSTALLATION_ID/credentials" \
  -H "$ACME_HEADER" -H 'Content-Type: application/json' \
  -d "{\"revision_token\":\"$QA014_REVISION_TOKEN\",\"credentials\":[{\"requirement_key\":\"calendar-oauth\",\"credential_kind\":\"delegated_credential\",\"reference_id\":\"delegated-calendar-acme\",\"status\":\"ready\",\"safe_summary\":{\"scope\":\"calendar.readonly\"}}]}" \
  | tee /tmp/qa014-configured.json
```

Expected: JSON contains `"readiness_state":"ready"`.

Preview binding eligibility.

```bash
curl -sS "$BASE_URL/admin/skill-registry/installations/$QA014_INSTALLATION_ID/eligibility" \
  -H "$ACME_HEADER" | tee /tmp/qa014-eligibility.json
```

Expected: JSON contains `"allowed":true`.

Try a stale revision update.

```bash
curl -sS -o /tmp/qa014-stale.json -w '%{http_code}\n' -X POST \
  "$BASE_URL/admin/skill-registry/installations/$QA014_INSTALLATION_ID/credentials" \
  -H "$ACME_HEADER" -H 'Content-Type: application/json' \
  -d "{\"revision_token\":\"$QA014_REVISION_TOKEN\",\"credentials\":[]}"
```

Expected: command prints `409`.

Run a redaction scan over API evidence.

```bash
grep -R -Ei 'password|refresh|bearer|credential_value|raw_payload|sk-' /tmp/qa014-*.json || true
```

Expected: no credential values, provider tokens, raw payloads, or secret-like
strings are present.

What this proves: the API lifecycle returns safe summaries and rejects stale
writes without exposing protected content.

## Troubleshooting

- If `curl` returns `401`, confirm `.env` was copied from `.env.qa014` and
  the `X-Local-Principal` header is present.
- If `curl` returns `404`, confirm the API server restarted after code changes.
- If migration fails, reset `multi_agent_platform_qa014` and rerun Alembic.
- If availability discovery is empty for Acme, confirm the grant command
  printed `204`.
- If readiness remains blocked after credential configuration, inspect
  `/tmp/qa014-configured.json` for the finding code.
- If the redaction scan prints a match, inspect whether it is a safe key name
  or an actual protected value.
- If full coverage fails during local partial testing, run focused tests with
  `--no-cov` and reserve the full command for the complete repository suite.
