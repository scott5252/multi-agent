# QA029 API And Database Guide

## Goal

QA029 proves that the React operations workbench is safe, scoped, typed, and useful for local operational triage.

The route under review is `/admin/app/operations`.

The primary API contract is `/admin/app/operations.json`.

The run debug contract is `/admin/app/operations/runs/{workflow_run_id}.json`.

The export contract is `/admin/app/operations/export`.

The backend owns all health, run, reliability, log, filter, and export summaries.

React renders generated TypeScript contracts and does not invent operational state.

The feature must not call live model providers.

The feature must not call Telegram.

The feature must not call external connector tools.

Expected: every QA029 value is deterministic, local, and safe to repeat.

What this proves: reviewers can validate operational workflows without production data.

## What This Guide Covers

- Local QA029 environment setup.
- React admin asset build.
- Protected workbench shell checks.
- Platform and tenant workbench envelope checks.
- Safe filter and problem-detail checks.
- Run timeline, branch, gateway, tool, and delivery contract checks.
- Reliability recovery and export snapshot checks.
- Denied and cross-tenant checks.
- Generated TypeScript contract drift checks.
- Backend, frontend, and full repository quality gates.
- Evidence under `/tmp/qa029-*`.

## How To Use This Guide

Run commands from the repository root.

When a command writes a `/tmp/qa029-*` file, keep it until reviewer notes are complete.

When a section says `Expected:`, record the result.

When a section says `What this proves:`, copy that note into review evidence if helpful.

Use `qa029_ui.md` for the browser walkthrough.

Use `qa029_user_guide.md` for a plain-language manual review script.

Do not use production credentials.

Do not connect to live providers.

Do not call Telegram.

Do not call external tools.

Do not paste private prompts, completions, memory contents, channel messages, provider responses, Telegram updates, connector outputs, stack traces, local paths, or tenant data from another organization into any QA note.

Expected: all command output is local and deterministic.

What this proves: the workbench can be reviewed safely by developers and QA reviewers.


## API Contract Checks

Check the protected React shell:

```bash
curl --fail --silent --show-error -H "X-Local-Principal: platform-admin" "$QA029_BASE_URL/admin/app/operations"
```

Expected: response contains `React Admin`.

Expected: response contains `/admin/app/bootstrap.json`.

What this proves: the shell is protected and can load the React bundle.

Check the platform envelope:

```bash
curl --fail --silent --show-error -H "X-Local-Principal: platform-admin" "$QA029_BASE_URL/admin/app/operations.json"
```

Expected: response contains `Operations workbench`.

Expected: response contains `Provider health`.

Expected: response contains `Daily briefing graph run`.

Expected: response contains `artifact-ref-qa029-platform`.

What this proves: platform operators can see platform-level operational summaries.

Check the tenant envelope:

```bash
curl --fail --silent --show-error -H "X-Local-Principal: tenant-admin-acme" "$QA029_BASE_URL/admin/app/operations.json?tenant_id=$QA029_ACME_TENANT_ID"
```

Expected: response contains `Tenant run health`.

Expected: response contains `artifact-ref-qa029-tenant`.

Expected: response does not contain `Provider health`.

What this proves: tenant administrators see tenant-scoped summaries, not platform-only data.

Check safe filtering:

```bash
curl --fail --silent --show-error -H "X-Local-Principal: platform-admin" "$QA029_BASE_URL/admin/app/operations.json?severity=warning&subsystem=gateway"
```

Expected: response contains `log-gateway-timeout`.

Expected: response does not contain `log-delivery-retry`.

What this proves: backend-owned filters narrow safe operational summaries.

Check rejected unsafe filter input:


Expected: `/tmp/qa029-bad-filter.json` contains `validation_error`.

Expected: `/tmp/qa029-bad-filter.json` does not echo `provider_payload`.

What this proves: unsafe input receives a safe problem detail.

Check run debug:

```bash
curl --fail --silent --show-error -H "X-Local-Principal: tenant-admin-acme" "$QA029_BASE_URL/admin/app/operations/runs/$QA029_RUN_ID.json?tenant_id=$QA029_ACME_TENANT_ID"
```

Expected: response contains `Calendar branch`.

Expected: response contains `allowed_read_only`.

Expected: response contains `mock_delivery_retry`.

## Troubleshooting

If the API cannot connect to PostgreSQL, rerun `docker compose up -d postgres`.

If the database still has old data, rerun the reset and seed commands.

If `/admin/app/operations` shows missing assets, rerun `cd frontend/admin && npm run build`.

If local login does not show `platform-admin`, confirm `.env.qa029` was copied to `.env`.

If a curl command returns 403 for a valid tenant admin, confirm the tenant seed command inserted Acme.

If a curl command exposes `Globex` in Acme evidence, stop and treat it as a tenant isolation regression.

If a curl command exposes `/Users/`, stop and treat it as an artifact reference regression.

If a curl command exposes `qa029-secret-value`, stop and treat it as a redaction regression.

If Playwright starts on a busy port, stop the existing local process and rerun the Playwright command.

If full coverage fails, inspect the missing file list before adding new tests.
