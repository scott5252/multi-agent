# QA017 Guide: Telegram Configuration Console

## Scope

Validate the server-rendered Telegram Configuration Console and JSON APIs for
safe readiness, tenant enablement, link-token controls, linked identity
inspection, and diagnostics.

## Environment

```bash
test ! -f .env || cp .env .env.autopilot-backup
cp specs/017-telegram-configuration-console/.env.qa017 .env
uv sync
docker compose up -d postgres
docker compose exec -T postgres sh -c 'dropdb -U postgres --if-exists multi_agent_platform_qa017 && createdb -U postgres multi_agent_platform_qa017'
uv run alembic upgrade head
```

## API Checks

```bash
curl --fail --silent -H "X-Local-Principal: platform-admin" \
  http://127.0.0.1:8000/admin/telegram/api/readiness

curl --fail --silent -H "X-Local-Principal: tenant-admin-acme" \
  http://127.0.0.1:8000/admin/telegram/api/config

curl --fail --silent -X POST -H "X-Local-Principal: tenant-admin-acme" \
  http://127.0.0.1:8000/admin/telegram/api/webhook/validate
```

Expected:

- Readiness returns `ready` without rendering `local-dev-secret`.
- Tenant config returns only Acme for `tenant-admin-acme`.
- Webhook validation reports `external_call_performed=false`.
- Globex admin requests for Acme tenant ids return `403`.

## Browser Checks

Open:

```text
http://127.0.0.1:8000/auth/local-login?redirect_to=/admin/telegram
```

Sign in as `platform-admin`, then select tenant scope if needed. Verify:

- The page title is "Telegram Configuration".
- Provider readiness shows safe reference labels only.
- Token and webhook secret values are not visible.
- The tenant form can enable Telegram and choose protected commands.
- A stale revision submission shows a conflict and preserves current values.
- Link-token issue shows the token once.
- Token lists show fingerprints only.
- Linked identities show masked Telegram user and chat identifiers.
- Diagnostics show category, status, trace id, timestamp, and safe summary.

## Redaction Checks

Search screenshots, HTML, logs, and JSON responses for these forbidden values:

- `qa017-fake-token`
- `local-dev-secret`
- private Telegram message text
- raw prompts
- run results
- full Telegram chat ids
- full Telegram user ids

None should appear in admin console pages or diagnostics.

## Goal

The goal of qa017 is to prove that Telegram Configuration can be managed
through safe admin surfaces.
It must prove platform readiness is understandable.
It must prove tenant enablement is isolated.
It must prove link tokens are safe.
It must prove linked identities are redacted.
It must prove diagnostics are useful and safe.
It must prove local QA does not contact Telegram.
It must prove reviewers can capture screenshots safely.

## How To Use This Guide

Run the steps in order.
Use only the qa017 database.
Use only the qa017 environment file.
Use `platform-admin` for platform checks.
Use `tenant-admin-acme` for Acme checks.
Use `tenant-admin-globex` for denial checks.
Save command output under `/tmp/qa017-api.log` when useful.
Save worker output under `/tmp/qa017-worker.log` when useful.
Save API response snippets under `/tmp/qa017-readiness.json`.
Save token-flow snippets under `/tmp/qa017-token-flow.json`.
Save redaction notes under `/tmp/qa017-redaction-notes.txt`.
Do not paste real Telegram credentials into this environment.

## Shared QA Variables

Set a base URL.

```bash
export QA017_BASE_URL=http://127.0.0.1:8000
export QA017_ACME_TENANT=11111111-1111-1111-1111-111111111111
export QA017_GLOBEX_TENANT=22222222-2222-2222-2222-222222222222
```

Expected: the variables identify the local API and seeded tenants.

Check readiness as platform admin.

```bash
curl --fail --silent -H "X-Local-Principal: platform-admin" \
  "$QA017_BASE_URL/admin/telegram/api/readiness" | tee /tmp/qa017-readiness.json
```

Expected: the response contains `ready`.
Expected: the response does not contain `local-dev-secret`.
Expected: the response does not contain `qa017-fake-token`.
What this proves: platform readiness is safe to inspect.

Check tenant config as Acme.

```bash
curl --fail --silent -H "X-Local-Principal: tenant-admin-acme" \
  "$QA017_BASE_URL/admin/telegram/api/config?tenant_id=$QA017_ACME_TENANT" \
  | tee /tmp/qa017-acme-config.json
```

Expected: the response contains the Acme tenant id.
Expected: the response contains a revision token.
What this proves: tenant admins can inspect their own Telegram config.

Check cross-tenant denial.

```bash
curl --silent --output /tmp/qa017-denied.json --write-out "%{http_code}" \
  -H "X-Local-Principal: tenant-admin-globex" \
  "$QA017_BASE_URL/admin/telegram/api/config?tenant_id=$QA017_ACME_TENANT"
```

Expected: the status code is `403`.
What this proves: tenant isolation fails closed.

Validate webhook locally.

```bash
curl --fail --silent -X POST -H "X-Local-Principal: tenant-admin-acme" \
  "$QA017_BASE_URL/admin/telegram/api/webhook/validate?tenant_id=$QA017_ACME_TENANT" \
  | tee /tmp/qa017-webhook-validation.json
```

Expected: `external_call_performed` is false.
What this proves: validation has no Telegram side effect.

Issue a link token.

```bash
curl --fail --silent -X POST -H "X-Local-Principal: tenant-admin-acme" \
  "$QA017_BASE_URL/admin/telegram/api/link-tokens?tenant_id=$QA017_ACME_TENANT" \
  | tee /tmp/qa017-token-flow.json
```

Expected: a link token is returned once.
Expected: the audit row contains only a fingerprint.
What this proves: token persistence is redaction-safe.

List token audits.

  "$QA017_BASE_URL/admin/telegram/api/link-tokens?tenant_id=$QA017_ACME_TENANT"

## Troubleshooting

If login fails, confirm `AUTH_MODE=local_principal`.
If the page is denied, confirm `telegram-config:read` permission.
If saves are denied, confirm `telegram-config:write` permission.
If token actions are denied, confirm `telegram-config:tokens` permission.
If diagnostics are denied, confirm `telegram-config:diagnostics` permission.
If the database is missing tenants, rerun migrations and seed setup.
If readiness is not ready, inspect `.env.qa017`.
If raw secrets appear, stop validation and file a security issue.
If stale conflict does not appear, repeat the two-tab flow.
If Playwright fails, confirm the API is on `127.0.0.1:8000`.
If worker startup fails, inspect `/tmp/qa017-worker.log`.
If API startup fails, inspect `/tmp/qa017-api.log`.
