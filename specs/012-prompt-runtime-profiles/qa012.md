# QA012: Prompt Library And Agent Runtime Profiles

## Goal

Validate that Spec `012` gives platform and tenant administrators governed
prompt-library and agent-runtime-profile workflows. This QA pass covers prompt
drafts, variable validation, safe fixture previews, immutable publication,
retirement, grants, profile validation, profile activation, profile resolution,
workflow validation hooks, model-skill prompt references, runtime pinning,
browser admin pages, audit-safe summaries, metrics, documentation, and
coverage evidence.

## What This Guide Covers

- Local setup for the dedicated database `multi_agent_platform_qa012`.
- Local-principal authentication for Acme tenant admin, Acme operator, Acme
  auditor, Globex tenant admin, and platform admin.
- Deterministic tenant seed data.
- Prompt Library API and browser pages under `/admin/prompt-runtime/prompts`.
- Agent Profile API and browser pages under `/admin/prompt-runtime/profiles`.
- Prompt variable validation and malformed template rejection.
- Safe fixture preview redaction and missing-fixture behavior.
- Immutable prompt publish and retirement from new use.
- Tenant grants for platform prompt versions.
- Runtime profile validation sections for prompts, model routing, memory
  policy, skills, tools, outputs, and tests.
- Tenant-over-platform profile resolution.
- Workflow prompt/profile validation adapter evidence.
- Model-skill prompt digest integration.
- Runtime configuration digest evidence for prompt library ids and digests.
- Security scans proving no raw secrets, credential values, provider tokens,
  unsafe prompt text, or rendered previews are present in saved QA evidence.
- Required automated quality gates.

## How To Use This Guide

Use two terminals from the repository root.

- Terminal A runs the API server.
- Terminal B runs setup, seed commands, `curl`, `jq`, SQL checks, browser
  checks, redaction scans, and automated tests.

Keep Terminal B open so shell variables remain available. Every command writes
reviewable evidence under `/tmp/qa012-*`. If a status code differs from the
expected value, inspect the corresponding saved file before continuing.

## Troubleshooting

- If API calls return `401`, confirm `.env` has `AUTH_MODE=local_principal`
  and requests include `X-Local-Principal`.
- If API calls return `500` for missing tables, rerun `uv run alembic upgrade
  head` against `multi_agent_platform_qa012`.
- If tenant scope fails, reseed tenants with the SQL block above.
- If publish fails with stale validation, rerun prompt validation and publish
  again without editing the draft in between.
- If activation fails, inspect `/tmp/qa012-profile-validate.json` for blocking
  profile findings.
- If the redaction scan fails, inspect the matching `/tmp/qa012-*` file and
  remove unsafe fixture values before retrying.
- If browser pages fail to render, check Terminal A for template errors and
  confirm `prompt_runtime.js` exists under `src/multi_agent_platform/web_admin/static`.
