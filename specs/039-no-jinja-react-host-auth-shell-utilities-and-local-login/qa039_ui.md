# QA039 UI Walkthrough: Spec 039 - No-Jinja React Host, Auth, Shell Utilities, And Local Login

## Goal

This walkthrough proves that a reviewer can sign in through the local-principal login page, open the React admin host, use the shell enough to verify navigation and scope context, and inspect saved-filter compatibility without touching any Jinja-rendered shell/auth page.

## How To Use This Guide

Follow the browser steps after the automated backend tests pass. Capture screenshots and short reviewer notes for every expected result. Store screenshots under `output/playwright/qa039_ui` and notes under `/tmp/qa039-ui-notes.md`.

What is happening: the reviewer is exercising the same local login and React host route that the automated Playwright validator uses.

Why this matters: later specs delete domain-specific Jinja pages, so the shell/auth entry path must be React or non-Jinja first.

## Browser Walkthrough

1. Open `http://127.0.0.1:8000/auth/local-login?redirect_to=/admin/app`.

Expected: the page title is `Local Login`.

What is happening: the browser receives a non-Jinja HTML page generated by the auth router.

Why this matters: local QA no longer depends on `auth/local_login.html`.

2. Confirm the page shows `Choose a local principal`.

Expected: the page lists `platform-admin`, `tenant-admin-acme`, and `tenant-user-acme` when the QA catalog is loaded.

What is happening: the local principal catalog is filtered server-side.

Why this matters: the browser renders choices but does not invent authorization state.

3. Select the `platform-admin` sign-in button.

Expected: the browser redirects to `/admin/app`.

What is happening: the backend validates the action token and sets the local-principal cookie.

Why this matters: later Playwright flows can authenticate without request headers.

4. Wait for the React admin shell to load.

Expected: the page contains `Admin` and visible shell navigation.

What is happening: `/admin/app` serves non-Jinja React host HTML and React fetches `/admin/app/bootstrap.json`.

Why this matters: the admin entry path has no server-side template dependency.

5. Refresh the browser while on `/admin/app`.

Expected: the same React host loads again.

What is happening: the host renderer handles browser refresh directly.

Why this matters: support bookmarks and reviewer refreshes remain safe.

6. Navigate to `http://127.0.0.1:8000/admin`.

Expected: the browser lands back on `/admin/app`.

What is happening: the old admin landing route redirects instead of rendering `admin_shell/index.html`.

Why this matters: old entry links remain useful without Jinja.

7. Navigate to `http://127.0.0.1:8000/admin/app/migration`.

Expected: the migration dashboard renders in React.

What is happening: the migration route uses the same non-Jinja host with a migration shell bootstrap.

Why this matters: the operator ledger remains available while deletion continues.

8. Navigate to `http://127.0.0.1:8000/admin/filters/workflows`.

Expected: the browser redirects to `/admin/app/saved-filters/workflows`.

What is happening: the old saved-filter page route no longer renders `admin_shell/saved_filters_page.html`.

Why this matters: shell utility pages are moving into React.

9. On the saved-filter React page, inspect the table or empty state.

Expected: the page shows either saved filters or a safe `No saved filters` state.

What is happening: React fetches `/admin/filters/workflows.json`.

Why this matters: saved-filter data remains backend-owned and tenant-scoped.

10. Sign out through `http://127.0.0.1:8000/auth/local-logout?redirect_to=/auth/local-login`.

Expected: the browser returns to local login.

What is happening: the local-principal cookie is deleted.

Why this matters: QA can switch principals without clearing browser storage manually.

11. Sign in as `tenant-admin-acme`.

Expected: `/admin/app` loads with tenant-scoped data.

What is happening: the cookie principal changes to the tenant admin.

Why this matters: tenant-scope checks must still work after Jinja removal.

12. Attempt to open a Globex tenant route by URL.

Expected: the response is denied or unavailable without the Globex label.

What is happening: backend authorization rejects cross-tenant access.

Why this matters: redirects and React fallback must not leak unauthorized tenant existence.

## Troubleshooting

- If local login is unavailable, confirm `.env.qa039` is copied and `AUTH_MODE=local_principal`.
- If platform-admin does not appear, check `LOCAL_PRINCIPAL_CATALOG_JSON`.
- If `/admin/app` shows asset unavailable, rebuild the frontend.
- If `/admin` does not redirect, rerun the backend route tests.
- If saved filters show a blank page, open browser devtools and verify `/admin/filters/workflows.json` returns success.
- If screenshots include stack traces, stop and record a redaction blocker.
- If Globex appears during an Acme denial, stop and record a tenant isolation blocker.
- If Playwright times out on `Admin`, repeat local login manually and inspect the cookie.
- If the browser opens an old Jinja page, record the route and stop before Spec 040.
