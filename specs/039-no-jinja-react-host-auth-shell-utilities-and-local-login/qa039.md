# QA039 Guide: Spec 039 - No-Jinja React Host, Auth, Shell Utilities, And Local Login

## Goal

This guide verifies that Spec 039 removes server-side Jinja rendering from the admin entry path, the local-principal login page, and shell utility handoffs while preserving authorization, tenant scope, redirects, saved-filter behavior, denied states, and rollback evidence.

The reviewer should be able to prove that `/admin/app`, `/admin/app/migration`, `/admin/app/saved-filters/workflows`, `/auth/local-login`, `/auth/local-login.json`, `/admin`, `/admin/scope`, and `/admin/filters/workflows` behave without `TemplateResponse` for the shell/auth surfaces changed by this spec.

The reviewer should also confirm that global Jinja infrastructure remains available for later specs. Spec 039 deletes only `admin_react/app.html` and `auth/local_login.html`; the shared `admin_shell` templates are retained because domain Jinja pages still extend them until Specs 040 through 046 retire those domains.

## What This Guide Covers

- Non-Jinja React host HTML for admin entry and deep React routes.
- Local-principal login HTML and JSON contracts without Jinja templates.
- Safe redirect behavior for `/admin`, `/admin/scope`, and saved-filter utility routes.
- Saved-filter JSON envelope and mutation compatibility.
- Auth0-shaped backend behavior through dependency overrides and route tests.
- Local-principal browser behavior through Playwright.
- Redaction checks for route responses, docs, screenshots, and reviewer notes.
- Retention evidence for shared shell templates that cannot be deleted yet.
- QA evidence paths under `/tmp/qa039-*`, `.data/qa039-artifacts`, and `output/playwright/qa039_ui`.

## How To Use This Guide

Run the automated commands first, then perform the manual checks only if automation passes. Keep a terminal log for each command under `/tmp/qa039-*` so the reviewer can compare failures without rerunning the full suite.

Use local-principal auth for browser checks. Use backend tests for Auth0-shaped behavior. Do not use real Auth0, Telegram, provider, credential, connector, or external tool calls for this spec.

What this proves: the browser-visible behavior is React or non-Jinja while the backend still owns auth, tenant scope, redirect sanitization, saved-filter validation, and redaction.

## Troubleshooting

- If `/admin/app` returns 401, open `/auth/local-login?redirect_to=/admin/app` and sign in as `platform-admin`.
- If `/admin/app` returns asset unavailable, run `cd frontend/admin && npm run build`.
- If `/admin` returns a 303, that is expected; follow the `Location` header to React.
- If `/admin/filters/workflows` returns a redirect, use `/admin/filters/workflows.json` for JSON evidence.
- If cross-tenant responses mention Globex, stop and treat it as a tenant isolation blocker.
- If QA docs validation fails on line counts, add concrete reviewer steps rather than filler.
- If route tests show `TemplateResponse` on admin entry or local login, stop before advancing to Spec 040.
- If full coverage fails, run the targeted tests first to separate coverage debt from Spec 039 regressions.
- If Docker is unavailable, do not point the validation runner at a non-QA database.
- If Playwright cannot find `Admin`, confirm the login flow submitted `platform-admin`.
