# QA Guide For Spec 004

This guide explains how to test the full Spec `004` durable orchestration
runtime flow.

Every step explains what you are doing, why it matters, and what success looks
like. The guide is meant for implementation reviewers, QA testers, and
operators validating the runtime after the feature is implemented.

## 1. What You Are Testing

Spec `004` delivers:

- durable runtime database tables and migration for runs, steps, bundles,
  worker leases, checkpoint references, handoffs, side-effect intents,
  approvals, lineage, timeline events, and retention metadata
- runtime JSON APIs for starting published workflow runs, inspecting runs,
  cancelling runs, listing timeline events, viewing handoffs and side effects,
  listing approval gates, submitting approval decisions, and traversing lineage
- background worker execution through LangGraph with PostgreSQL checkpoints
- per-run version-bundle pinning so registry changes do not alter in-flight
  runs
- worker lease expiry and takeover behavior with a 2-minute default
- contract-gated agent handoffs with failure-route diagnostics
- approval pause-resume behavior that survives worker restarts
- nested subworkflow lineage from parent to child and child to parent
- side-effect intent idempotency so retries and crash resumes do not repeat
  completed external actions
- audit, metrics, traces, retention defaults, README updates, PR review notes,
  and automated test evidence

## 24. Troubleshooting

- `400 workflow is not published`: complete Section 5 and use the published
  `workflow_version_bundle_id` before starting a run.
- `403 outside current scope`: check the principal and tenant visibility for
  the published workflow version or run.
- `409 idempotency conflict`: change the `idempotency_key` or inspect the
  original run created by that key.
- run remains `pending`: confirm the worker is running and can claim work.
- run remains `paused`: inspect `/approval-gates` and submit an authorized
  decision.
- worker cannot claim work: check active leases, expiry time, tenant quota, and
  worker permission.
- resume fails with bundle mismatch: inspect the run bundle digest and confirm
  resume uses the per-run execution bundle, not the latest registry version.
- invalid handoff is consumed: this is a release blocker; receiver consumption
  must be gated by a `valid` handoff envelope.
- side effect repeated after crash: this is a release blocker; applied
  side-effect intents must return the recorded result on resume.
