# QA041: Spec 041 - Governance Full React Parity And Jinja Removal

## Goal

This guide verifies that Spec 041 moves governance browser journeys to React and removes governance-owned Jinja templates safely.

Reviewers should prove that `/admin/app/governance` is the browser entry point for provider, prompt, runtime profile, model-skill routing, policy history, run provenance, credential readiness, prompt preview, profile resolution, and legacy redirect evidence.

Reviewers should also prove that old governance browser URLs redirect to React or return safe non-Jinja errors after the old templates have been deleted.

What this proves: governance operators keep their workflows while the active governance browser surface no longer renders Jinja templates.

## What This Guide Covers

- React governance dashboard and legacy route mapping contracts.
- Provider list, detail, edit, catalog, probe, credential reference, and direct-call guardrail summaries.
- Prompt library list, edit, history, safe preview, version detail, and form-post compatibility.
- Runtime profile list, edit, history, version detail, profile resolution, and form-post compatibility.
- Model-skill routing, policy history, and run provenance React destinations.
- Old governance route redirects with safe query preservation.
- Governance-owned template deletion evidence.
- Retained helper evidence for historical view-model modules.
- Auth0-shaped route authorization through backend tests.
- Local-principal browser behavior through Playwright.
- Tenant isolation, denied states, and redaction checks.
- QA evidence paths under `/tmp/qa041-*`, `.data/qa041-artifacts`, and `output/playwright/qa041_ui`.

## How To Use This Guide

Run the automated commands first.

Then perform the manual checks only if automation passes.

Keep terminal logs under `/tmp/qa041-*`.

Do not use real Auth0, Telegram, provider, credential, connector, or external tool calls.

What this proves: every review artifact is deterministic and safe to share with project reviewers.

## Troubleshooting

If `/admin/app/governance` returns auth-required, open `http://127.0.0.1:8000/auth/local-login` and select `platform-admin`.

If the legacy redirect checks return `401`, confirm the `X-Local-Principal` header value is present.

If PostgreSQL reset fails, confirm Docker is running and no other command is connected to `multi_agent_platform_qa041`.

If the React host returns stale assets, rerun `cd frontend/admin && npm run build`.

If the route scanner finds governance templates, confirm the deleted files were not restored during conflict resolution.

If redaction scans fail, treat the output as a blocker and do not attach it to reviewer artifacts.

If Playwright cannot click local login, confirm `AUTH_MODE=local_principal` and the local principal catalog is loaded from `.env.qa041`.
