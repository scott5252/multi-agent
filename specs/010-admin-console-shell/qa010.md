# QA010: Admin Console Shell

## Goal

Validate that Spec `010` delivers a shared, server-rendered admin console shell
for the multi-agent platform. The checks cover platform and tenant scope
display, authorization-aware navigation, route preservation, fail-closed
denials, itemized navigation audit evidence, common empty/error states, safe
messages and breadcrumbs, saved filters, no-JS fallback behavior, docs, and
automated evidence.

This guide is written for a non-developer reviewer. It gives copy/paste
commands, expected outputs, and troubleshooting notes so the reviewer can tell
an implementation gap from a regression.

## What This Guide Covers

- Local QA setup with a dedicated PostgreSQL database:
  `multi_agent_platform_qa010`.
- Local-principal auth for platform admin, tenant admin, non-admin operator,
  auditor, and cross-tenant admin roles.
- Deterministic Acme and Globex tenants.
- `/admin` platform and tenant shell rendering.
- Tenant scope propagation through `tenant_id`.
- Authorization-aware navigation groups: Workflows, Model And Skill Config,
  Run Inspection, Reliability, and Access.
- Existing route preservation for workflow, model-skill, run inspection, and
  reliability pages.
- Safe fail-closed behavior for missing auth, non-admin users, forged tenant
  ids, and unavailable audit evidence.
- Common empty/error state rendering.
- Saved-filter creation, listing, restoration, deletion, and scope isolation.
- Redaction scans for secrets, credentials, prompts, memory payloads, run
  payloads, and stack traces.
- Required automated evidence: Ruff, format, mypy, focused tests, and full
  coverage.

Current implementation notes:

- The shell frame is fully server-rendered. `admin_shell.js` is optional and
  only enhances scope switching and saved-filter deletion prompts.
- Run replay keeps JSON behavior for default API clients. Browsers or curl
  requests with `Accept: text/html` render the replay template inside the shell.
- Model-skill UI pages are thin, safe wrappers over existing service helpers.
- Saved filters are enabled only on useful list/investigation pages.

## How To Use This Guide

Use two terminal windows from the repository root.

- Terminal A runs the API.
- Terminal B runs setup, `curl`, SQL, redaction scans, and quality commands.

Keep Terminal B open for the full pass because it stores shell variables and
writes evidence files under `/tmp/qa010-*`.

If any command returns the wrong HTTP status, stop and inspect the saved output
file named in that step before continuing.

## Environment

1. Copy the QA010 environment file:

   ```bash
   cp specs/010-admin-console-shell/.env.qa010 .env
   ```

   Expected: no output. The app is now configured for local-principal auth,
   fake QA010 secret refs, and `multi_agent_platform_qa010`.

2. Confirm required CLI tools:

   ```bash
   curl --version | head -1
   jq --version
   ```

   Expected: both commands print versions. If `jq` is unavailable, manually
   inspect the saved HTML and SQL results.

3. Clean old QA010 files:

   ```bash
   find /tmp -type f \( -name 'qa010-*.html' -o -name 'qa010-*.json' -o -name 'qa010-*.txt' \) -exec rm -f {} +
   ```

   Expected: no output.

4. Install dependencies:

   ```bash
   uv sync
   ```

   Expected: dependencies install or are already synchronized.

5. Start PostgreSQL:

   ```bash
   docker compose up -d postgres
   ```

   Expected: the local PostgreSQL 16 service is running.

6. Create the dedicated QA database:

   ```bash
   docker compose exec -T postgres sh -c \
     'psql -U postgres -d postgres -tc "SELECT 1 FROM pg_database WHERE datname = '\''multi_agent_platform_qa010'\''" | grep -q 1 || createdb -U postgres multi_agent_platform_qa010'
   ```

   Expected: no output. QA010 data is isolated from other local databases.

7. Apply migrations:

   ```bash
   uv run alembic upgrade head
   ```

   Expected: migrations complete, including `0010_admin_console_shell`.

8. Seed deterministic tenants:

   ```bash
   docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa010 -v ON_ERROR_STOP=1 <<'SQL'
   INSERT INTO tenants (
     tenant_id, slug, display_name, status, created_at, updated_at
   ) VALUES
     ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP),
     ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP)
   ON CONFLICT (tenant_id) DO UPDATE SET
     slug = EXCLUDED.slug,
     display_name = EXCLUDED.display_name,
     status = EXCLUDED.status,
     updated_at = CURRENT_TIMESTAMP;

   DELETE FROM admin_saved_filters
   WHERE tenant_id IN (
     '11111111-1111-1111-1111-111111111111',
     '22222222-2222-2222-2222-222222222222'
   ) OR principal_id IN (
     'platform-admin',
     'tenant-admin-acme',
     'tenant-admin-globex',
     'operator-acme'
   );

   DELETE FROM audit_events
   WHERE action LIKE 'admin_shell.%'
     AND actor_id IN (
       'platform-admin',
       'tenant-admin-acme',
       'tenant-admin-globex',
       'operator-acme'
     );
   SQL
   ```

   Expected: SQL completes with `INSERT 0 2` or `INSERT 0 0` plus deletes.

## Saved Filters: Save And List

Save a workflow filter in Acme tenant scope:

```bash
curl -sS -w "%{http_code}\n" \
  -H "$QA010_TENANT_HEADER" \
  -X POST \
  "$QA010_BASE_URL/admin/filters/workflows?tenant_id=$QA010_ACME_TENANT" \
  -d 'filter_key=workflow-list' \
  -d 'display_name=Drafts' \
  -d 'criteria={"status":"draft","slug":"customer-intake"}' \
```

## Troubleshooting

- `401` on every route: confirm `X-Local-Principal` header names match
  `.env.qa010`.
- `403` for tenant admin: confirm the request includes the Acme `tenant_id`.
- Empty navigation: confirm the principal has `tenant_admin` or
  `platform_admin`.
- PostgreSQL connection errors: confirm `docker compose up -d postgres` ran and
  `multi_agent_platform_qa010` exists.
- Saved filter does not show up: confirm the same principal and same active
  scope are used for save and list.
- Redaction scan fails: inspect the matching `/tmp/qa010-*` file and verify the
  text is not a raw secret, prompt, memory payload, run payload, or stack trace.
- Full coverage fails: keep the focused admin shell test output and inspect the
  missing coverage lines before review sign-off.
