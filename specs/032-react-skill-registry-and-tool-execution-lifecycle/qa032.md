# QA032 API And Database Guide

## Goal

QA032 proves that the React skill lifecycle workspace is safe, scoped, typed, and useful for platform and tenant administrators.

The route under review is `/admin/app/skills`.

The primary dashboard contract is `/admin/app/skills/bootstrap.json`.

The discovery contract is `/admin/app/skills/discovery.json`.

The installations contract is `/admin/app/skills/installations.json`.

The diagnostics contract is `/admin/app/skills/diagnostics.json`.

The audit contract is `/admin/app/skills/audit.json`.

Package candidate actions post to `/admin/app/skills/packages/candidates`.

Validation and publication actions post to protected candidate routes.

Tenant grant, quarantine, and withdrawal actions post to protected package routes.

Tenant install, credential, smoke-test, and eligibility preview actions post to protected installation routes.

Expected: platform administrators can save candidates, validate candidates, publish immutable versions, update tenant grants, quarantine packages, and withdraw packages.

Expected: tenant administrators cannot mutate package publication state.

Expected: tenant administrators can discover granted packages, install skills, configure credential references, refresh readiness, inspect connector diagnostics, preview binding eligibility, and review audit evidence.

Expected: all skill lifecycle output is generated by backend contracts and generated TypeScript.

Expected: local validation does not call live Auth0.

Expected: local validation does not call Telegram.

Expected: local validation does not call model providers.

Expected: local validation does not call external connector tools.

Expected: local validation does not resolve real credential values.

What this proves: reviewers can validate skill package publication, tenant lifecycle actions, governed tool readiness, and binding evidence without exposing sensitive package or connector data.

## What This Guide Covers

- Local QA032 environment setup.
- React admin asset build.
- Protected skill lifecycle shell checks.
- Platform candidate, validation, publication, grant, quarantine, and withdrawal checks.
- Tenant discovery, installation, credential reference, smoke-test, connector readiness, and binding preview checks.
- SkillExecutionGateway diagnostic summary checks.
- Audit timeline and safe diff summary checks.
- Local-principal and Auth0-shaped authorization checks.
- Redaction, tenant isolation, and fail-closed checks.
- Generated TypeScript contract drift checks.
- Backend, frontend, and full repository quality gates.
- Evidence under `/tmp/qa032-*`.

## How To Use This Guide

Run commands from the repository root.

When a command writes a `/tmp/qa032-*` file, keep it until reviewer notes are complete.

Use `qa032_ui.md` for the browser walkthrough.

Use `qa032_user_guide.md` for a plain-language manual review script.

Do not use real provider credentials.

Do not connect to live providers.

Do not call Telegram.

Do not call external tools.

Do not paste secrets into manifest fields.

Do not paste raw package manifests, credential values, connector request or response bodies, private messages, memory contents, tool outputs, stack traces, local paths, or tenant data from another organization into any QA note.

Expected: all command output is local and deterministic.

Expected: skill lifecycle diagnostics are safe summaries and artifact references.

Expected: credential references appear as labels and fingerprints only.

What this proves: the skill lifecycle route can be reviewed safely by developers and QA reviewers.

Copy the QA032 environment:

```bash
cp specs/032-react-skill-registry-and-tool-execution-lifecycle/.env.qa032 .env
```

Expected: `.env` references `multi_agent_platform_qa032`.

```bash

uv run alembic upgrade head
```

Seed local tenants:

```bash
docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa032 -v ON_ERROR_STOP=1 -c "INSERT INTO tenants (tenant_id, slug, display_name, status, created_at, updated_at) VALUES ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP), ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP) ON CONFLICT (slug) DO NOTHING"
```

Create evidence directories:

```bash

```

Capture the tenant dashboard contract:

```bash
curl -sS -H "X-Local-Principal: tenant-admin-acme" "http://127.0.0.1:8000/admin/app/skills/bootstrap.json?tenant_id=11111111-1111-1111-1111-111111111111" > /tmp/qa032-tenant-skills.json
```

Expected: `/tmp/qa032-platform-skills.json` contains `platform_publication`.

Expected: `/tmp/qa032-tenant-skills.json` contains tenant discovery, installation, readiness, binding, diagnostics, and audit summaries.

Expected: neither file contains raw manifests, credential values, authorization headers, connector payloads, local paths, or Globex data in the Acme tenant view.

## API Checks

Check platform publication:

```bash
curl -sS -H "X-Local-Principal: platform-admin" "$QA032_BASE_URL/admin/app/skills/bootstrap.json" | tee /tmp/qa032-platform-bootstrap.json
```

Expected: the response includes `react-skill-lifecycle`.

Expected: the response includes `platform_publication`.

Expected: the response includes safe manifest summary and manifest digest.

Create a package candidate:

```bash
curl -sS -X POST "$QA032_BASE_URL/admin/app/skills/packages/candidates" -H "Content-Type: application/json" -H "X-Local-Principal: platform-admin" -d '{"manifest_text":"safe pasted fixture","uploaded_fixture_id":"qa032-uploaded-manifest","candidate_revision":null,"idempotency_key":"qa032-candidate"}' | tee /tmp/qa032-candidate-create.json
```

Expected: the response status is `accepted`.

Expected: upload precedence is mentioned.

Expected: no pasted manifest body is echoed.

Validate a blocked candidate:

```bash
curl -sS -X POST -H "X-Local-Principal: platform-admin" "$QA032_BASE_URL/admin/app/skills/packages/candidates/qa032-candidate/validate?ready=false" | tee /tmp/qa032-candidate-blocked.json
```

Expected: the response status is `validation_error`.

Publish a candidate:

```bash
curl -sS -X POST "$QA032_BASE_URL/admin/app/skills/packages/candidates/qa032-candidate/publish" -H "Content-Type: application/json" -H "X-Local-Principal: platform-admin" -d '{"candidate_revision":"candidate-rev-qa032-current","confirmed":true,"idempotency_key":"qa032-publish"}' | tee /tmp/qa032-candidate-publish.json
```

Expected: the response status is `accepted`.

Expected: the publication lifecycle status is `published`.

Check tenant discovery:

```bash
curl -sS -H "X-Local-Principal: tenant-admin-acme" "$QA032_BASE_URL/admin/app/skills/discovery.json?tenant_id=$QA032_ACME_TENANT_ID" | tee /tmp/qa032-discovery.json
```

## Troubleshooting

- `401 missing local principal header or cookie`: sign in through `/auth/local-login`.
- `403 insufficient role`: use `platform-admin` for publication or `tenant-admin-acme` for tenant lifecycle actions.
- `403 tenant scope denied`: confirm the `tenant_id` query matches the local-principal tenant.
- `validation_error` during publication: refresh validation and smoke-test evidence.
- `stale_conflict`: reload `/admin/app/skills` and retry with the latest revision token.
- `dependency_unavailable`: confirm database migrations and React assets are current.
- Missing screenshots: rerun Playwright with `--start-processes`.

Expected: troubleshooting steps do not require live credentials or external calls.
