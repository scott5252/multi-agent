# QA027 API And Database Guide

## Goal

QA027 proves that Spec 027 delivers the modern React admin shell and local design system without weakening the security model from the server-rendered admin console.

The feature under review is the shared shell at `/admin/app`.

The backend remains authoritative for authentication, active scope, navigation visibility, command search, fallback links, and redaction.

The browser receives only safe shell metadata.

The browser must not invent hidden navigation, raw tenant data, saved filter criteria, prompt text, completion text, memory content, provider payloads, credential values, or stack traces.

This guide focuses on API, database, build, and contract evidence.

Use `qa027_ui.md` for browser-only walkthrough evidence.

Use `qa027_user_guide.md` when a non-developer reviewer needs a slower step-by-step script.

## What This Guide Covers

- Local setup for the QA027 database and deterministic principals.
- React admin asset build and generated type contract checks.
- Protected shell bootstrap behavior for local-principal reviewers.
- Protected command search behavior for local-principal and Auth0-shaped callers.
- Denied and cross-tenant behavior for shell and search metadata.
- Redaction checks for safe summaries and forbidden values.
- Backend and frontend quality gates that must pass before Spec 028 starts.
- Evidence files under `/tmp/qa027-*` and browser screenshots under `output/playwright/qa027_ui`.

## How To Use This Guide

Run commands from the repository root unless a command explicitly changes directory.

Keep a terminal open for the API process and a second terminal for the worker if you are not using the automated validation runner.

When this guide says `Expected:`, save the command output or a reviewer note.

When this guide says `What this proves:`, include that sentence in the reviewer notes if the evidence is accepted.

Do not paste real secrets into this environment.

Do not point QA027 at a production database.

Do not run live provider, Telegram, credential, or external connector calls.

Use the static fake references in `.env.qa027`.

Expected: all evidence is tenant-safe and redaction-safe.

What this proves: the shell can be validated locally without external side effects.

## Troubleshooting

If `/health/live` fails, confirm `.env` was copied from `.env.qa027` and the API process was restarted.

If migrations fail, reset `multi_agent_platform_qa027` and rerun `uv run alembic upgrade head`.

If bootstrap returns 401, include `-H "X-Local-Principal: tenant-admin-acme"` or sign in through local login.

If bootstrap returns 403 for Acme, confirm the Acme tenant row exists and the principal catalog uses the Acme tenant ID.

If the manifest endpoint reports `manifest_missing`, run `cd frontend/admin && npm run build`.

If TypeScript fails after schema edits, run `uv run python scripts/frontend/generate_admin_react_types.py`.

If command search returns no results for `workflow`, inspect `/admin/app/bootstrap.json` to confirm authorized navigation includes Workflows.

If Playwright cannot find shell text, confirm the API process is running with `REACT_ADMIN_ENABLED=true`.

If coverage fails below 90 percent, run the focused React admin tests first and inspect the coverage report for unrelated gaps.

If a denied response contains `Globex`, stop the rollout and investigate tenant guard behavior before proceeding.

Expected: troubleshooting does not require changing production settings.

What this proves: common failures can be resolved without weakening QA isolation.
