# QA070 Guide: React Workflow Graph And Agent Role Builder

## Goal
QA070 proves that the React Admin workflow builder can edit workflow roles, contracts, graph topology, join policies, approval gates, subworkflow references, and layout annotations through visible browser controls.
The feature uses the existing React workflow document save route.
The backend remains authoritative for authorization, tenant scope, validation findings, idempotency, stale conflict recovery, audit summaries, and publish readiness.
The seeded Acme workflow draft is `70707070-6669-4670-8670-000000000070`.
The primary tenant is `11111111-1111-1111-1111-111111111111`.
The cross-tenant negative principal is `tenant-admin-globex`.

## What This Guide Covers
This guide covers deterministic environment setup, database migration, QA070 seed data, role editing, contract editing, graph topology editing, join policy editing, approval and subworkflow editing, save/reload persistence, validation findings, desktop and mobile Playwright evidence, and curl regression review.
It validates the existing `/admin/app/workflows/drafts/{workflow_draft_id}/save` route family.
It does not require live provider calls.
It does not require Telegram calls.
It does not require external connector calls.
It does not require real Auth0 callbacks.
It does not require production credentials.
It does not ask reviewers to inspect raw prompt bodies, completions, memory contents, private channel messages, provider payloads, raw tool payloads, raw test transcripts, stack traces, or local filesystem paths.
Any protected raw material in API responses, screenshots, logs, docs, or curl output is a QA failure.

## How To Use This Guide
Run the commands from the repository root.
Keep the QA070 environment isolated from development data.
Save command output under `/tmp/qa070-*` so evidence can be attached to review notes without editing repository files.
Stop at the first failed Expected result.
Keep the response body that failed.
Do not run live external probes during this guide.
Do not add real credentials to `.env`.
Do not hand-edit workflow setup through raw JSON in the browser.
Use the API commands only as verification aids.

## API Check 1: Load Builder Detail
```bash
curl --fail --silent \
  -H "$QA070_HEADER" \
  "$QA070_BASE_URL/admin/app/workflows/drafts/$QA070_WORKFLOW_DRAFT_ID/detail.json?tenant_id=$QA070_TENANT_ID" \
  | tee /tmp/qa070-detail.json \
  | jq '.draft.document.workflow_key, (.draft.document.roles | length), (.draft.document.nodes | length), (.draft.document.join_policies | length)'
```

Expected: workflow key `qa070-graph-role-builder`, role count `3`, node count `6`, and join count `1` are printed.
What this proves: the seed draft contains roles, topology, and a join before browser editing begins.

## API Check 2: Save Rich Workflow Document
```bash

  -H "$QA070_HEADER" \
```

## Troubleshooting
If login does not show local principals, confirm `.env` was copied from `.env.qa070`.
If the workflow draft is missing, rerun `uv run python scripts/qa/seed_workflow_graph_role_builder_qa070.py`.
If PostgreSQL cannot reset the database, run `docker compose up -d postgres` and retry.
If save returns stale conflict, reseed QA070 or update the payload revision to the current draft revision.
If save returns validation errors during the positive check, inspect `.validation.findings` in `/tmp/qa070-save.json`.
If Playwright cannot find `New agent`, confirm the desktop flow clicked `Add role` and saved successfully.
If screenshots show overlapping text, capture the viewport size and keep the screenshot for UI review.
If a redaction scan finds protected text, stop and attach the evidence path.
If curl regression fails, inspect `.data/curl_test_runs/qa070-after-spec`.
If full coverage fails, review the uncovered lines before moving to Spec 071.
