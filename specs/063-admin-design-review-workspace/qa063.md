# QA063 Guide: Admin Design Review Workspace

## Goal

This guide validates qa063, the Admin Design Review workspace.
The workspace lets tenant admins inspect live design review sessions.
It also lets them create sessions, launch coordinator rounds, and record manual decisions.
Every row must come from the database.
No product screen may invent a session, verdict, quorum decision, or handoff.
The guide focuses on deterministic local-principal QA.
It also records enough evidence for reviewers to confirm tenant isolation and redaction.

## What This Guide Covers

This guide covers the backend workspace envelope.
It covers the React route under `/admin/app/design-reviews`.
It covers the live session list.
It covers the selected-session detail.
It covers revision summaries.
It covers round history.
It covers reviewer verdict summaries.
It covers quorum decision summaries.
It covers manual-resolution controls.
It covers final handoff references.
It covers empty tenant behavior.
It covers denied tenant behavior.
It covers safe copy and visible redaction checks.
It covers the automated commands required before marking the spec complete.

## How To Use This Guide

Run commands from the repository root.
Use a clean terminal for API logs.
Use a second terminal for curl checks.
Use a third terminal for frontend checks when needed.
Save command output under `/tmp/qa063-*`.
Keep screenshots under `output/playwright/qa063_ui`.
Record only safe summaries and identifiers in review notes.
Do not paste raw prompts, completions, secrets, provider payloads, private messages, memory contents, unauthorized payloads, or external tool payloads into evidence.
If a command fails, stop and capture the command, exit code, and safe error summary.
Expected: every persisted design review record is live database state.

## Troubleshooting

If the API cannot connect to PostgreSQL, confirm Docker is running.
If migrations fail, recreate `multi_agent_platform_qa063`.
If local login fails, confirm the app copied `.env.qa063`.
If the workspace is empty for Acme, rerun the QA063 seed script.
If Globex shows Acme records, stop and treat it as a tenant-isolation blocker.
If visible copy says mock, fixture, React, FastAPI, Pydantic, SQLAlchemy, or Jinja, stop and treat it as a product-copy blocker.
If unsafe content appears in the envelope, stop and treat it as a redaction blocker.
If Playwright cannot click login, open `http://127.0.0.1:8000/auth/local-login?redirect_to=/admin/app/design-reviews` manually.
If TypeScript fails after schema changes, regenerate or adjust the local workspace types.
If curl regression fails outside the design-review section, inspect the first failed command before rerunning.
