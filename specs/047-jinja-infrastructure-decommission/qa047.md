# QA047 Jinja Infrastructure Decommission Guide

## Goal

Prove qa047 removes the server-side template runtime while preserving React browser access, local-principal login, old-link compatibility, tenant isolation, and redaction-safe evidence. What this proves: runtime browser delivery no longer depends on Jinja infrastructure, and rollback is an operational redeploy rather than an in-process template toggle.

## What This Guide Covers

- Final runtime import scanners for Jinja infrastructure symbols.
- Server template and legacy static asset deletion evidence.
- Direct dependency removal from pyproject.toml and uv.lock.
- React-only migration dashboard evidence at /admin/app/migration.
- Local login, /admin/app, /runs, and /runs/{run_id} compatibility paths.
- Auth0-shaped backend behavior and AUTH_MODE=local_principal browser behavior.
- Redaction, tenant isolation, generated contracts, frontend build, and coverage gates.

## How To Use This Guide

Run the commands in order. Save terminal output under /tmp/qa047-api-evidence.txt, /tmp/qa047-quality-evidence.txt, and /tmp/qa047-playwright-evidence.txt when reviewing manually. Each command has an Expected: line that reviewers can compare against.

## Troubleshooting

If a runtime scanner fails, inspect the exact marker and remove the template runtime dependency rather than weakening the scanner. If React build fails, rebuild frontend/admin and rerun generated contract checks. If Playwright cannot log in, verify local-principal catalog entries in .env.qa047. If a route leaks a path or stack trace, fix the backend safe problem response first.
