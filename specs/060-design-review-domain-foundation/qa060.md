# QA060 Guide: Spec 060 - Design Review Domain Foundation

## Goal

This guide verifies the design review domain foundation.

Spec 060 adds durable records for design review sessions, revisions, reviewer
rounds, reviewer assignments, reviewer verdicts, quorum decisions, manual
decisions, and development handoffs.

The backend must keep tenant data separated.

The backend must expose only safe summaries, digests, artifact references, and
metadata.

The backend must reject raw secrets, authorization headers, private prompts,
completions, private channel messages, memory contents, and raw tool payloads.

The API must support idempotent session creation.

The API must support idempotent manual-decision recording.

The API must present truthful empty states for tenants with no design reviews.

The API must let platform administrators inspect tenant-scoped design review
metadata through explicit tenant context.

Expected: Acme can create and inspect Acme design review records.

Expected: Globex cannot read Acme design review records.

Expected: Globex receives an empty state for its own empty tenant scope.

Expected: platform-admin can inspect Acme records when a tenant id is supplied.

Expected: all persisted text is safe summary text.

Expected: no QA output contains `Authorization:` or provider credential values.

## Troubleshooting

If the API does not start, inspect `/tmp/qa060-api.log`.

If the worker exits early, inspect `/tmp/qa060-worker.log`.

If migration fails, confirm Docker PostgreSQL is running.

If the seed script fails, confirm `.env` was copied from `.env.qa060`.

If create-session returns `401`, confirm the `X-Local-Principal` header.

If create-session returns `403`, confirm the tenant id matches the principal.

If Globex list is not empty, rerun the database reset command.

If the manual decision replay fails, confirm the idempotency key is unchanged.

If Playwright cannot find `design`, open `http://127.0.0.1:8000/openapi.json`
and confirm the API process is serving the new router.

If the curl test fails in a later section, inspect the generated script in the
curl run directory.

Expected: rerunning the seed script is safe.

Expected: rerunning the API commands is safe when idempotency keys stay stable.
