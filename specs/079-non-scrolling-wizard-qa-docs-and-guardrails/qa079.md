# QA079 Guide: Non-Scrolling Wizard QA, Docs, And Guardrails

## Goal

Prove Non-Scrolling Wizard QA, Docs, And Guardrails works through the generic workflow onboarding wizard while preserving tenant scope, backend-owned readiness, redaction, and the 1280 x 800 no-scroll contract. This guide references qa079 and .env.qa079. Evidence should be saved under /tmp/qa079-evidence and under the configured artifact root. What this proves: a reviewer can validate the slice without live providers or tutorial-specific setup.

## What This Guide Covers

-
The feature focus is QA docs, Playwright no-scroll journeys, screenshot evidence, accessibility and performance guardrails, redaction sweeps, and hard-coded tutorial terminology scans.
-
The API surface is the validation manifests, existing React Admin browser routes, generated API contracts, QA document validator, and final stability gate commands.
-
The browser path starts at local login and then uses visible UI links only.
-
The workflow may use arbitrary scenario text such as Supplier Risk Intake or Incident Triage.
-
The guide keeps API and curl checks secondary to browser validation.
-
The guide treats backend validation, evidence freshness, and publish readiness as authoritative.
-
The guide checks that screenshots do not expose unsafe raw data.
-
The guide records no-scroll evidence at 1280 x 800.

## How To Use This Guide

1. Read the expected result after each step before running it.
2. Use a fresh local shell for environment setup.
3. Use the in-app browser or Playwright for visual evidence.
4. Keep screenshots and logs under the qa artifact paths.
5. If a step fails because of a backend blocker, capture the blocker and do not bypass it with browser state.
6. If a screen scrolls vertically at 1280 x 800, mark the run failed.
7. If raw secret-like text appears, mark the run failed.
8. If a step requires editing the browser URL after login, mark the run failed.

## Troubleshooting

- If local login fails, confirm AUTH_MODE=local_principal and the local principal catalog value.
- If the wizard action is missing, confirm the principal is authorized for workflow registry access.
- If the wizard opens but shows dependency unavailable, inspect the API log under /tmp for the safe trace id.
- If create fails, check the workflow key for duplicate or invalid characters.
- If save fails with stale revision, reload through the visible recovery action and retry.
- If validation blocks publish, do not override browser state; capture the blocker.
- If evidence is stale, rerun deterministic evidence through the Test Bench path and refresh readiness.
- If a screenshot shows vertical scroll, split the step or reduce visible collection density.
- If generated type freshness fails, regenerate types from backend contracts and rerun typecheck.
- If coverage fails in a selected single-test run, rerun the full coverage command for final evidence.
