# QA072 Guide: Custom Workflow Test Evidence And Publish Setup

## Goal
QA072 proves that workflow setup can attach required Test Bench evidence to a workflow draft and surface publish readiness without browser-only shortcuts.
The source of truth is the existing Test Bench suite, case, run, artifact, and publication requirement records.
The workflow document stores only safe requirement pointers and safe status summaries.
The backend evaluates current evidence against the exact workflow draft revision.
The browser shows evidence state, safe diagnostics, and publish blockers.
The browser does not invent passing evidence.
The browser does not override backend publish readiness.
The browser does not expose protected prompts, completions, private payloads, credentials, provider headers, tool payloads, stack traces, local paths, or unauthorized tenant labels.

The seeded workflow revision is `72727272-3333-4672-8672-000000000072`.

The seeded current run is `72727272-4003-4672-8672-000000000072`.

## What This Guide Covers
This guide covers deterministic QA setup, database migration, QA072 seed data, workflow builder evidence rendering, Test Bench suite visibility, deterministic run launch, publish gate evaluation, stale and failed evidence checks, tenant isolation, redaction review, browser screenshots, and curl regression review.
It validates the existing workflow builder detail route.
It validates the existing workflow save route.
It validates the existing workflow publish gate route.
It validates the existing React Test Bench route family.
It validates the existing `/admin/agent-tests` route family through the curl regression suite.
It does not add a new public API route.
It does not require live provider calls.
It does not require live Telegram calls.
It does not require external connector calls.
It does not require real Auth0 callbacks.
It does not require production credentials.
It does not require reviewer access to protected run transcripts.
It does not require copying raw evidence payloads into screenshots.
Any protected material in evidence output is a failure.

## How To Use This Guide
Run commands from the repository root.
Use the isolated QA072 database.
Use local-principal authentication only.
Use `tenant-admin-acme` for positive checks.
Use `tenant-admin-globex` for cross-tenant denial checks.
Save API output under `/tmp/qa072-*`.
Save browser screenshots under `output/playwright/qa072_ui`.
Stop at the first failed Expected result.
Keep the failed response body for review.
Do not run live external probes.
Do not add real credentials to `.env`.
Do not hand-edit database records during validation.
Do not mark evidence as passing in the browser without a persisted Test Bench run.
Treat missing, stale, failed, or cross-tenant evidence as expected blockers.
Treat a current passing run for the exact draft revision as the only ready state.

## Troubleshooting
If the local login page does not load, confirm the API process is running on port 8000.
If `tenant-admin-acme` is not visible, confirm `.env.qa072` was copied to `.env`.
If the workflow list is empty, rerun `uv run python scripts/qa/seed_workflow_test_evidence_qa072.py`.
If the detail API returns 404, confirm the QA072 workflow draft ID.
If the publish gate is blocked for missing validation, rerun the seed command.
If the publish gate is blocked for missing evidence, inspect the current suite ID in the workflow document.
If the publish gate is stale, confirm the run target revision equals the workflow revision ID.
If the Test Bench suite detail is missing, confirm migrations reached head.
If a live provider mode is shown, confirm `.env.qa072` disables live probes.
If protected material appears in screenshots, discard the screenshot and rerun from a clean QA database.
If browser text overlaps, inspect `frontend/admin/src/styles/admin.css`.
If frontend tests fail after static asset rebuild, rerun generated type freshness.
If Docker is not running, start Docker and rerun the validation manifest.
If PostgreSQL contains stale data, drop and recreate `multi_agent_platform_qa072`.
If a command cannot find Python dependencies, rerun `uv sync`.
If Node dependencies are stale, run `cd frontend/admin && npm ci`.
If the curl regression fails, inspect `.data/curl_test_runs/qa072-after-spec`.
