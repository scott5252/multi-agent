# QA071 Guide: Prompt Profile Creation And Per-Agent Binding UI

## Goal
QA071 proves that the React Admin workflow builder can author prompt and runtime profile bindings for individual agent roles without exposing raw prompt content in workflow summaries, graph panels, validation output, mutation summaries, screenshots, or JSON inspector surfaces.
The feature uses existing prompt runtime APIs, existing profile runtime APIs, and the existing workflow document save route.
The workflow document stores safe prompt/profile reference keys and version identifiers.
The browser presents per-role readiness so reviewers can see complete, incomplete, and blocked binding states.
The seeded Acme workflow draft is `71717171-6669-4671-8671-000000000071`.
The seeded prompt lineage is `71717171-1000-4671-8671-000000000071`.
The seeded prompt version is `71717171-1004-4671-8671-000000000071`.
The seeded runtime profile is `71717171-2000-4671-8671-000000000071`.
The seeded profile version is `71717171-2004-4671-8671-000000000071`.
The primary tenant is `11111111-1111-1111-1111-111111111111`.

## What This Guide Covers
This guide covers deterministic environment setup, database migration, QA071 seed data, prompt and profile API visibility, workflow builder catalog projection, per-agent binding controls, save/reload persistence, validation findings, redaction checks, desktop and mobile Playwright evidence, and curl regression review.
It validates the existing `/admin/prompt-runtime/api/prompts` route family.
It validates the existing `/admin/prompt-runtime/api/profiles` route family.
It validates the existing `/admin/app/workflows/drafts/{workflow_draft_id}/save` route family.
It validates that `/admin/app/workflows/lookups.json` and the selected draft builder payload expose safe reference options.
It does not require live provider calls.
It does not require Telegram calls.
It does not require external connector calls.
It does not require real Auth0 callbacks.
It does not require production credentials.
It does not ask reviewers to inspect raw prompt bodies in browser screenshots.
It does not ask reviewers to collect raw prompt bodies as durable QA evidence.
Any protected secret, credential value, provider authorization header, raw completion, memory content, private channel message, raw external tool payload, stack trace, local filesystem path, or unauthorized tenant label in QA evidence is a failure.

## API Check 7: Reject Blocked Profile Reference
```bash
jq '.revision="2" | .idempotency_key="qa071-blocked-profile" | .document.prompt_profile_references[0].readiness_status="missing"' "$QA071_SAVE_PAYLOAD" > /tmp/qa071-blocked-profile-payload.json
curl --fail --silent \
  -H "$QA071_HEADER" \
  -H "Content-Type: application/json" \
  -X POST \
  --data @/tmp/qa071-blocked-profile-payload.json \
```

What this proves: backend validation still blocks non-ready prompt/profile references before persistence.

## API Check 8: Reject Unsafe Prompt-Like Text In Workflow Summary
```bash
jq '.revision="2" | .idempotency_key="qa071-unsafe-role" | .document.roles[0].purpose="raw prompt copied into workflow role summary"' "$QA071_SAVE_PAYLOAD" > /tmp/qa071-unsafe-payload.json
curl --fail --silent \
  -H "$QA071_HEADER" \
```

What this proves: workflow summaries cannot become raw prompt storage.

## Troubleshooting
If the seed command fails with `DATABASE_URL is required for QA071 seed`, copy `.env.qa071` to `.env` or export `DATABASE_URL`.
If the seed command fails on missing tables, run `uv run alembic upgrade head`.
If the browser does not show `QA071 Prompt Profile Builder`, confirm the seed printed the QA071 draft ID and the local login used `tenant-admin-acme`.
If the lookup catalog is empty, call `/admin/app/workflows/lookups.json` with `workflow_draft_id=$QA071_WORKFLOW_DRAFT_ID`.
If the readiness badge does not change after activation, confirm `Research agent` is selected in the role selector.
If `Draft saved` does not appear, inspect `/tmp/qa071-api/server.log` and the browser console for safe problem details.
If the blocked reference negative path unexpectedly saves, inspect the validation response for prompt/profile readiness mapping.
If the redaction scan finds a local path, delete the evidence file and rerun from a clean local server log.
If Playwright cannot click local login, confirm local-principal auth is active in `.env`.
If `npm ci` fails, rerun `uv sync` and check Node.js satisfies the repository version range.
