# QA069 Guide: Workflow Document Authoring Contracts And Mutation APIs

## Goal
QA069 proves that the React Admin workflow builder can load, save, replay, reject, and diagnose complete workflow documents through safe JSON contracts.
The feature extends the existing React workflow route family instead of introducing a second editor surface.
The backend remains the authority for authorization, revision tokens, idempotency, validation findings, and redaction.
The seeded Acme workflow draft is `69696969-6669-4669-8669-000000000069`.
The primary tenant is `11111111-1111-1111-1111-111111111111`.
The cross-tenant negative principal is `tenant-admin-globex`.

## What This Guide Covers
This guide covers deterministic environment setup, database migration, seed data, full document save, idempotent replay, stale conflict, invalid graph validation, generated TypeScript freshness, backend tests, frontend tests, Playwright smoke, and curl regression.
It validates the existing `/admin/app/workflows/drafts/{workflow_draft_id}/save` route family.
It does not require live provider calls, Telegram calls, external connector calls, Auth0 callbacks, or production credentials.
It does not ask reviewers to inspect raw prompt bodies, completions, memory contents, private messages, provider payloads, tool payloads, stack traces, or local filesystem paths.
It treats any protected raw material in API responses, logs, screenshots, docs, or curl output as a QA failure.

## How To Use This Guide
Run the setup commands in order from the repository root.
Save API responses under `/tmp/qa069-*` so evidence can be reviewed without editing repository files.
Use `jq` checks exactly as written when possible.
Each check includes an Expected line and a What this proves line.
If one check fails, stop and keep the response body under `/tmp/qa069-*` for investigation.
Do not run live external probes while using this guide.

## API Check 1: Load Editor State
```bash
curl --fail --silent \
  -H "$QA069_HEADER" \
  "$QA069_BASE_URL/admin/app/workflows/drafts/$QA069_WORKFLOW_DRAFT_ID/detail.json?tenant_id=$QA069_TENANT_ID" \
  | tee /tmp/qa069-detail.json \
  | jq '.draft.revision, .draft.document.workflow_key, (.draft.section_summaries | length)'
```
Expected: revision `1`, workflow key `qa069-workflow-document-authoring`, and a positive section summary count are printed.
What this proves: the React detail contract includes the complete canonical document and safe section summaries.

## API Check 2: Save Complete Document
```bash
curl --fail --silent \
  -H "$QA069_HEADER" \
  -H "Content-Type: application/json" \
  -X POST \
  --data @"$QA069_SAVE_PAYLOAD" \
  "$QA069_BASE_URL/admin/app/workflows/drafts/$QA069_WORKFLOW_DRAFT_ID/save?tenant_id=$QA069_TENANT_ID" \
  | tee /tmp/qa069-save.json \
  | jq '.status, .revision, .editor_state.document.editor_annotations.section_notes.metadata'
```
Expected: status `accepted`, revision `2`, and the QA069 section note are printed.
What this proves: the browser-facing save route persists the full document, not only display name and description.

## API Check 3: Replay Exact Save
```bash
curl --fail --silent \
  -H "$QA069_HEADER" \
  -H "Content-Type: application/json" \
  -X POST \
  --data @"$QA069_SAVE_PAYLOAD" \
  "$QA069_BASE_URL/admin/app/workflows/drafts/$QA069_WORKFLOW_DRAFT_ID/save?tenant_id=$QA069_TENANT_ID" \
  | tee /tmp/qa069-replay.json \
  | jq '.status, .idempotency.replayed, .revision'
```
Expected: status `idempotent_replay`, replayed `true`, and revision `2` are printed.
What this proves: durable idempotency fingerprints prevent duplicate revisions for exact duplicate saves.

## API Check 4: Reject Stale Save
```bash
jq '.idempotency_key="qa069-workflow-document-stale" | .force_stale=true' "$QA069_SAVE_PAYLOAD" > /tmp/qa069-stale-payload.json
curl --fail --silent \
  -H "$QA069_HEADER" \
  -H "Content-Type: application/json" \
  -X POST \
  --data @/tmp/qa069-stale-payload.json \
  "$QA069_BASE_URL/admin/app/workflows/drafts/$QA069_WORKFLOW_DRAFT_ID/save?tenant_id=$QA069_TENANT_ID" \
  | tee /tmp/qa069-stale.json \
  | jq '.status, .stale_conflict.submitted_revision, .stale_conflict.current_revision'
```
Expected: status `stale_conflict`, submitted revision `1`, and current revision `2` are printed.
What this proves: stale browser tabs cannot overwrite newer durable draft revisions.

## API Check 5: Reject Idempotency Conflict

jq '.description="Different payload with reused QA069 key" | .document.description="Different payload with reused QA069 key"' "$QA069_SAVE_PAYLOAD" > /tmp/qa069-idempotency-conflict-payload.json

  -H "$QA069_HEADER" \

## Troubleshooting
If the seed script cannot connect, confirm `.env` was copied from `.env.qa069` and Postgres is running.
If the save returns stale before API Check 2, reset the QA database and rerun migrations plus the seed script.
If replay returns `accepted`, confirm the same payload file and idempotency key were reused.
If invalid graph returns stale, update the invalid graph payload revision to the current revision from `/tmp/qa069-save.json`.
If generated type checks fail, rerun `uv run python scripts/frontend/generate_admin_react_types.py` and inspect the diff.
If browser login fails, clear the local-principal cookie and retry through `/auth/local-login`.
If protected text appears in evidence, stop QA and treat the response as a redaction bug.
