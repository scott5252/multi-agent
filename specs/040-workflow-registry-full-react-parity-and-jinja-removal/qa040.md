# QA040 Guide: Spec 040 - Workflow Registry Full React Parity And Jinja Removal

## Goal

This guide verifies that Spec 040 provides workflow registry browser parity through React and retires workflow-owned Jinja templates safely.

The reviewer should be able to prove that `/admin/app/workflows` is the browser entry point for workflow list, create, draft editing, graph preview, validation, publish readiness, revision history, published version detail, sharing summary, and legacy route evidence.

The reviewer should also prove that old workflow browser URLs redirect to React or return safe non-Jinja errors after workflow templates and `workflow_studio.js` have been removed.

What this proves: workflow authors keep their browser journey while workflow-owned Jinja rendering is removed from the active route surface.

## What This Guide Covers

- React workflow registry envelope and create envelope.
- React workflow builder detail envelope with registry, create, sharing, version, revision, validation, graph, and publish fields.
- React workflow legacy route mapping envelope.
- Old workflow browser route redirects with safe query preservation.
- Legacy form post compatibility for create, save, validate, restore, copy, and publish actions.
- Workflow-owned template deletion evidence.
- `workflow_studio.js` deletion evidence.
- `workflow_studio.css` retention evidence.
- Auth0-shaped backend authorization behavior through tests.
- Local-principal browser behavior through Playwright.
- Tenant isolation, denied states, and redaction checks.
- QA evidence paths under `/tmp/qa040-*`, `.data/qa040-artifacts`, and `output/playwright/qa040_ui`.

## How To Use This Guide

Run the automated commands first.

Then perform the manual checks only if automation passes.

Keep terminal logs under `/tmp/qa040-*`.

Keep screenshots under `output/playwright/qa040_ui`.

Use local-principal auth for browser checks.

Use backend tests for Auth0-shaped behavior.

Do not use real Auth0, Telegram, provider, credential, connector, or external tool calls.

What this proves: every review artifact is deterministic and safe to share with project reviewers.

## Troubleshooting

- If `/admin/app/workflows` returns 404, rebuild React assets and confirm `REACT_ADMIN_ENABLED=true`.
- If local login loops, confirm `.env` was copied from `.env.qa040` and the cookie name is `map_local_principal`.
- If old workflow routes return 200 HTML, inspect `src/multi_agent_platform/api/routers/admin_workflow_ui.py` for restored TemplateResponse code.
- If `workflow_studio.js` reappears after a build, check static copy scripts and remove only workflow-owned JS references.
- If `workflow_studio.css` is reported as a failure, confirm the reviewer understands it is retained with blocker evidence for shared non-Jinja styling.
- If cross-tenant checks show Globex labels to an Acme principal, stop and treat that as a tenant isolation blocker.
- If coverage fails from unrelated tests, preserve the failing log under `/tmp/qa040-coverage.log` and do not advance the autopilot queue until the active failure is understood.
- If Playwright cannot find `Workflow`, inspect `/tmp/qa040-api.log`, `/tmp/qa040-worker.log`, and the screenshot under `output/playwright/qa040_ui`.
