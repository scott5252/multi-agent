# QA052 Guide: Skill Lifecycle React Live Data

## Goal

Prove qa052 replaces deterministic skill lifecycle React payloads with live
repository-backed package, grant, installation, credential, diagnostic, binding,
and audit data.

Expected: fresh QA databases render truthful empty states.

Expected: seeded QA databases render only persisted skill lifecycle rows.

Expected: a browser user can save a credential reference and the database shows
the persisted readiness update.

Expected: no raw manifests, credential values, provider authorization headers,
connector payloads, tool outputs, smoke-test transcripts, stack traces, local
filesystem paths, or unauthorized tenant labels are exposed.

What this proves: qa052 removes the production QA032 skill lifecycle rows
instead of moving them into a different production helper.

## What This Guide Covers

This guide covers the local QA environment for `multi_agent_platform_qa052`.

It validates these React skill routes:

- `/admin/app/skills`
- `/admin/app/skills/bootstrap.json`
- `/admin/app/skills/discovery.json`
- `/admin/app/skills/installations.json`
- `/admin/app/skills/diagnostics.json`
- `/admin/app/skills/audit.json`
- `/admin/app/skills/installations/{installation_id}/credentials`
- `/admin/app/skills/eligibility/preview`

Expected: each JSON route can show live data or an explicit empty state.

Expected: platform-only publication actions remain platform-only.

Expected: tenant-scoped credential actions remain tenant-scoped.

Expected: Globex cannot see Acme seeded skill data.

What this proves: authorization and tenant isolation are part of the live-data
replacement, not a separate manual assumption.

## Setup Commands

Copy the QA environment.

```bash
cp specs/052-skill-lifecycle-react-live-data/.env.qa052 .env
uv sync
```

Expected: `.env` now contains qa052 settings.

Start PostgreSQL and reset only the qa052 database.

```bash
docker compose up -d postgres
docker compose exec -T postgres sh -c 'dropdb -U postgres --if-exists multi_agent_platform_qa052 && createdb -U postgres multi_agent_platform_qa052'
uv run alembic upgrade head
```

Expected: only `multi_agent_platform_qa052` is recreated.

Seed local tenants.

```bash
docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa052 -v ON_ERROR_STOP=1 -c "INSERT INTO tenants (tenant_id, slug, display_name, status, created_at, updated_at) VALUES ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP), ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP) ON CONFLICT (slug) DO NOTHING"
```

Expected: Acme and Globex tenant rows exist.

Seed skill lifecycle rows.

```bash
uv run python scripts/qa/seed_skill_lifecycle_qa052.py
```

Expected: the command prints `Seeded QA052 skill lifecycle records`.

What this proves: all QA skill rows are created by a documented setup flow.

## Troubleshooting

If the API cannot connect to the database, confirm `.env.qa052` was copied to
`.env`.

If Alembic fails, recreate only `multi_agent_platform_qa052`.

If the seeded package is missing, rerun
`uv run python scripts/qa/seed_skill_lifecycle_qa052.py`.

If Playwright cannot find `Save reference`, confirm the login principal is
`tenant-admin-acme`.

If post-UI verification reports a pending credential, rerun Playwright and then
rerun `uv run python scripts/qa/verify_skill_lifecycle_qa052.py`.

If Globex sees Acme package data, stop and treat it as a tenant isolation
blocker.

If any response contains raw manifests, credential values, authorization
headers, connector payload bodies, raw tool outputs, stack traces, or local
absolute paths, stop and treat it as a redaction blocker.

Expected: troubleshooting never changes production data or external services.

Expected: fixes remain scoped to qa052 skill lifecycle surfaces.
