# QA019 Guide: Operations Console Logs And Performance

## Scope

Validate the server-rendered Operations Console and JSON APIs for platform
health, dependency readiness, worker capacity, provider status, channel status,
usage throughput, redacted operational logs, bounded filtering, CSV export, and
authorization.

## Environment

```bash
test ! -f .env || cp .env .env.autopilot-backup
cp specs/019-operations-console-logs-performance/.env.qa019 .env
uv sync
docker compose up -d postgres
docker compose exec -T postgres sh -c 'dropdb -U postgres --if-exists multi_agent_platform_qa019 && createdb -U postgres multi_agent_platform_qa019'
uv run alembic upgrade head
docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa019 -c "INSERT INTO tenants (tenant_id, slug, display_name, status, created_at, updated_at) VALUES ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP), ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP) ON CONFLICT (slug) DO NOTHING;"
mkdir -p .data/qa019-artifacts output/playwright/qa019_ui
```

Expected:

- `.env` points to `multi_agent_platform_qa019`.
- Storage writes to `.data/qa019-artifacts`.
- Local principals include `platform-admin`, `auditor`, and tenant admins.
- Tenant rows exist for Acme and Globex denial audit evidence.
- No production secret, provider token, prompt body, or raw channel payload is
  required.

## API Checks

Start the API:

```bash
uv run uvicorn multi_agent_platform.api.main:app --host 127.0.0.1 --port 8000
```

Check the dashboard as a platform admin:

```bash
curl --fail --silent -H "X-Local-Principal: platform-admin" \
  http://127.0.0.1:8000/admin/operations/api/dashboard | tee /tmp/qa019-dashboard.json
```

Expected:

- Response includes `health_status`, `status_cards`, `dependencies`,
  `capacity`, `providers`, `usage`, `logs`, and `redaction_notice`.
- Status cards include system health, worker capacity, model providers,
  Telegram and channels, request latency, token throughput, and error rate.
- The response does not include raw prompts, completions, secrets, credentials,
  memory content, stack traces, or channel payloads.

Check redacted log filtering as an auditor:

```bash
curl --fail --silent -H "X-Local-Principal: auditor" \
  "http://127.0.0.1:8000/admin/operations/api/logs?component=runtime&limit=25" \
  | tee /tmp/qa019-logs.json
```

Expected:

- Response shape is `{ "items": [...], "filters": {...} }`.
- Every row has safe `summary` and `details`.
- Links target run inspection, reliability, model provider, or usage pages only
  when the actor is authorized.
- The query is bounded by `limit`.

Check tenant-admin denial:

```bash
test "$(curl --silent --output /tmp/qa019-tenant-denied.json --write-out '%{http_code}' \
  -H "X-Local-Principal: tenant-admin-acme" \
  http://127.0.0.1:8000/admin/operations/api/dashboard)" = "403"
```

Expected:

- Tenant admins are denied in v1 even if their local-principal permissions
  accidentally include operations codes.
- Denial does not reveal platform operational data.

Check export:

```bash
curl --fail --silent -X POST \
  -H "X-Local-Principal: platform-admin" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:8000/admin/operations/api/logs/export \
  -d '{"filters":{"limit":25}}' | tee /tmp/qa019-export.json
```

Expected:

- Response includes `export_id`, `artifact_uri`, `artifact_sha256`,
  `artifact_size_bytes`, `row_count`, `filters`, `requested_by`, and
  `audit_event_id`.
- Artifact content is CSV with redacted operational fields only.
- The export or denial is recorded through existing inspection-access audit
  records.

## Browser Checks

Open:

```text
http://127.0.0.1:8000/auth/local-login?redirect_to=/admin/operations
```

Sign in as `platform-admin`, then verify:

- The page title is `Operations Console`.
- Admin shell navigation includes `Operations Console`.
- Cards summarize health, worker capacity, DB pool pressure, object storage,
  model providers, Telegram and channels, reliability state, latency,
  throughput, token throughput, and error rate.
- The filters include trace id, tenant id, run id, component, severity, status,
  dependency, and limit.
- The operational log table renders safe summaries and safe details only.
- Export controls are visible for the platform admin.
- The redaction notice is visible before screenshots are captured.

## Redaction Checks

Search screenshots, HTML, JSON responses, and CSV exports for forbidden values:

- raw prompt text
- model response text
- channel message text
- secret values
- provider API keys
- authorization headers
- memory content
- raw payloads
- stack traces
- unauthorized tenant labels or identifiers

None should appear in `/admin/operations`, `/admin/operations/api`, or export
artifacts.

## Goal

The goal of qa019 is to prove platform operations can be reviewed safely from a
browser and from JSON APIs.
It must prove platform admins can see platform-wide operations signals.
It must prove auditors can inspect redacted logs.
It must prove tenant admins are denied in v1.
It must prove raw logs are not read directly.
It must prove redacted CSV export artifacts are safe.
It must prove export attempts leave audit-safe evidence.
It must prove log filtering is bounded and performant.
It must prove screenshots are safe to attach to a review.

## Troubleshooting

If local login fails, verify `AUTH_MODE=local_principal`.
If the platform admin is missing, recopy `.env.qa019`.
If the dashboard is sparse, remember an empty QA database may have no runtime
events yet.
If export fails, verify `.data/qa019-artifacts` exists.
If tenant admin access succeeds, stop and treat it as a release blocker.
If raw prompt text appears, stop and treat it as a release blocker.
If CSV export contains a forbidden value, stop and treat it as a release
blocker.
If Playwright fails to start, run the API validation first and inspect
`/tmp/qa019-api.log`.
