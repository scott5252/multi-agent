# QA054 Guide: Membership And Access React Live Data

## Goal

Prove qa054 replaces deterministic membership and access React payloads with
live repository-backed principal identities, invitations, tenant memberships,
role grants, access decisions, support override records, and audit records.

Expected: an empty tenant shows a truthful empty membership state.

Expected: a seeded tenant shows only persisted membership rows.

Expected: the React page can create an invitation through the backend.

Expected: the database shows the invitation and audit record after the browser
action.

Expected: no raw email, full subject, provider token, credential value, local
path, stack trace, or unauthorized tenant label is rendered.

What this proves: qa054 removes the fixed QA034 membership data path instead of
moving deterministic rows into another production helper.

## What This Guide Covers

This guide covers the local QA environment for `multi_agent_platform_qa054`.

It validates these React membership routes:

- `/admin/app/memberships`
- `/admin/app/memberships/bootstrap.json`
- `/admin/app/memberships/invitations`
- `/admin/app/memberships/access-history.json`
- `/admin/app/memberships/audit.json`

Expected: each JSON route can show live data or an explicit empty state.

Expected: Acme can see the QA054 seeded membership records.

Expected: Globex sees an empty state and cannot see Acme rows.

Expected: access history is derived from persisted access decision records.

Expected: support override evidence is derived from persisted override rows.

Expected: audit responses expose governed safe summaries only.

What this proves: the live-data replacement includes route behavior, tenant
isolation, support override evidence, redaction, and persisted browser actions.


```bash
docker compose up -d postgres
```

Expected: the local PostgreSQL container is running.

```bash

```

Expected: only `multi_agent_platform_qa054` is dropped and recreated.

Run migrations.

```bash
uv run alembic upgrade head
```

Expected: Alembic reaches the latest revision.

Seed local tenants.

```bash
docker compose exec -T postgres psql -U postgres -d multi_agent_platform_qa054 -v ON_ERROR_STOP=1 -c "INSERT INTO tenants (tenant_id, slug, display_name, status, created_at, updated_at) VALUES ('11111111-1111-1111-1111-111111111111', 'acme', 'Acme', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP), ('22222222-2222-2222-2222-222222222222', 'globex', 'Globex', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP) ON CONFLICT (slug) DO NOTHING"
```

Expected: Acme and Globex tenant rows exist.

Seed qa054 membership records.

```bash
uv run python scripts/qa/seed_membership_qa054.py
```

Expected: the command prints `Seeded QA054 membership live records`.

Create artifact directories.

```bash
mkdir -p .data/qa054-artifacts output/playwright/qa054_ui
```

Expected: QA artifact directories exist.

Start the app.

```bash
uv run uvicorn multi_agent_platform.api.main:app --host 127.0.0.1 --port 8000
```

Expected: the API is reachable on `http://127.0.0.1:8000`.

## Troubleshooting

If the login page does not show `tenant-admin-acme`, confirm `.env` was copied
from `.env.qa054`.

If the API returns an empty Acme page, rerun `uv run python scripts/qa/seed_membership_qa054.py`.

If Playwright cannot click `Invite`, confirm the page is loaded at
`/admin/app/memberships` after local login.

If verifier reports no Playwright invitation, rerun Playwright before running
the verifier.

If Globex shows Acme records, stop and treat that as a tenant isolation blocker.

If unsafe text appears in screenshots, stop and treat that as a redaction
blocker.

If Docker is unavailable, start PostgreSQL locally with the same database name
and keep the connection string in `.env.qa054`.
