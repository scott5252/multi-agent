# QA058: Live-Only UI Decommission Gate

## Goal

Validate Spec 058 end to end: production admin UI routes must be classified by
the live-only gate, source and built assets must have zero blocking fixture
findings, route probes must cover empty and seeded states, and reviewer-facing
evidence must stay redaction-safe.

## What This Guide Covers

- Source scanner validation for production admin route handlers and projection services.
- Built asset scanning for generated browser assets under `src/multi_agent_platform/web_admin/static/react`.
- Route inventory validation for static `/admin/app` JSON routes.
- Empty-state and seeded-state route probe expectations.
- QA058 seed setup that reuses persisted records from the completed live-data specs.
- Playwright evidence for the migration live-data inventory UI.
- Post-UI verification through `scripts/qa/verify_live_only_gate_qa058.py`.
- Curl regression through the shared multi-agent curl test runner.
- Redaction checks for secrets, raw prompts, private messages, local paths, and unauthorized tenant labels.

## How To Use This Guide

1. Work from the repository root.
2. Use only the dedicated QA058 database.
3. Do not call real Auth0, provider, Telegram, credential, connector, or outbound services.
4. Keep `.env.qa058` as the source for local-principal QA.
5. Capture terminal output under `/tmp/qa058-*` if a reviewer needs raw evidence.
6. Keep screenshots under `output/playwright/qa058_ui`.
7. Keep generated scanner reports under `.data/qa058-artifacts`.
8. Treat any blocking scanner finding as a release blocker.
9. Treat the remaining mapped bootstrap marker as deferred to Spec 059.
10. Do not commit until the full remaining roadmap is complete.

What this proves: QA058 can be replayed locally without relying on hidden chat state.

## Troubleshooting

- If source scan reports blocking findings, inspect the `source_path` and remove production fixture data.
- If route target count changes, update `live_data_route_targets()` and route tests together.
- If built assets contain stale markers, rebuild the frontend and rerun `generate_admin_react_types.py --check`.
- If the projected endpoint is denied, verify `tenant_id` and `X-Local-Principal`.
- If Playwright cannot find `Live-data guardrails`, confirm the redirect path is `/admin/app/migration`.
- If the verifier report contains a local path, fix the report writer before rerunning validation.
- If curl regression fails, inspect `.data/curl_test_runs/qa058-after-spec`.

Expected: troubleshooting never requires real provider or Telegram calls.
