# QA028 API And Database Guide

## Goal

QA028 proves that shared React admin data contracts and form patterns are safe, typed, scoped, and reusable.

The feature under review is the harmless patterns page at `/admin/app/patterns`.

The backend owns the page envelope.

The backend owns filter choices.

The backend owns sorting choices.

The backend owns mutation results.

The backend owns export snapshots.

React renders only generated TypeScript contracts.

React does not move domain rules into the browser.

This guide focuses on API, contract, database, and quality evidence.

Use `qa028_ui.md` for browser walkthrough evidence.

Use `qa028_user_guide.md` for a plain-language manual review script.

Expected: QA028 validates reusable patterns without mutating real domain state.

What this proves: future React admin pages have a safe contract baseline.

## What This Guide Covers

- Local QA028 environment setup.
- React admin asset build.
- Protected page envelope checks.
- Safe problem detail checks.
- Sample mutation result checks.
- Stale conflict and idempotency checks.
- Filter, sorting, pagination, and export snapshot checks.
- Denied and cross-tenant checks.
- Generated TypeScript contract checks.
- Backend and frontend quality gates.
- Evidence under `/tmp/qa028-*`.

## Troubleshooting

If `/admin/app/patterns.json` returns 401, include `X-Local-Principal`.

If it returns 403 for Acme, seed the Acme tenant row.

If invalid filters return 200, stop and inspect backend filter validation.

If export snapshots include local paths, stop and inspect export summary redaction.

If frontend tests fail after schema edits, regenerate TypeScript contracts.

If Playwright does not find `Forms`, rebuild React assets.

If coverage fails, run the focused tests first.

Expected: troubleshooting does not require disabling tenant guards.

What this proves: failures can be resolved without weakening security.
