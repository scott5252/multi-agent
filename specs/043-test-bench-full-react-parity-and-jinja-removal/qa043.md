# QA043: Spec 043 - Test Bench Full React Parity And Jinja Removal

## Goal

This guide verifies that Spec 043 completes the agent and workflow test bench
browser migration to React.

Reviewers should prove that `/admin/app/test-bench` is the only browser UI for
suite review, suite creation, case authoring, safe run launch, run diagnostics,
artifact metadata, publish-gate evidence, audit timeline evidence, and old
direct-link recovery.

Reviewers should also prove that old `/admin/agent-tests/ui...` browser URLs no
longer render `agent_tests` Jinja templates. Safe old GET routes redirect to
React with tenant and object context preserved. Old form POST routes still
execute the same backend behavior, then redirect to React with a mutation state.
Unsafe or invalid legacy requests fail closed with non-Jinja responses.

What this proves: operators keep the complete test bench workflow while the
retired Jinja templates cannot render protected suite, case, run, artifact, or
gate data.

## What This Guide Covers

- React test bench host and bootstrap contract.
- Retained `/admin/agent-tests` JSON APIs for API clients.
- Legacy `/admin/agent-tests/ui` GET redirects.
- Legacy suite, case, and run form POST compatibility redirects.
- Tenant-scoped suite and run direct links.
- Safe run launch modes and mocked execution behavior.
- Run progress, trace, artifact, and result summaries.
- Publish-gate states including stale, missing, failed, passed, audit
  unavailable, and redaction unavailable evidence.
- Deleted `src/multi_agent_platform/web_admin/templates/agent_tests` templates.
- Router scanner evidence proving `admin_agent_tests.py` no longer renders
  `agent_tests` templates.
- Backend Auth0-shaped tests and local-principal browser checks.
- Redaction checks for raw prompts, completions, memory contents, private
  payloads, raw artifacts, storage paths, provider headers, and secrets.

## How To Use This Guide

Run the automated commands first.

Then perform manual browser checks only if automation passes.

Keep terminal logs under `/tmp/qa043-*`.

Keep browser screenshots under `output/playwright/qa043_ui`.

Use local-principal authentication for manual browser checks.

Use backend tests for Auth0-shaped authorization and cross-tenant checks.

Do not use real Auth0, Telegram, provider, credential, connector, model, or
external tool calls.

Do not paste private workflow payloads, prompts, completions, memory contents,
or local filesystem paths into the test bench.

What this proves: every review artifact is deterministic, tenant-scoped, and
safe to share with project reviewers.

## Troubleshooting

- If login loops, confirm `LOCAL_PRINCIPAL_COOKIE_NAME=map_local_principal`.
- If a route returns `401`, confirm the local login cookie or
  `X-Local-Principal` header is present.
- If a tenant route returns `403`, confirm `tenant_id` matches the selected
  principal.
- If React assets return `404`, run `cd frontend/admin && npm run build`.
- If old routes return `200` with HTML, stop and inspect
  `admin_agent_tests.py`.
- If a run payload contains raw prompt, completion, memory, or artifact content,
  preserve the evidence file and treat it as a blocker.
- If a gate appears current for the wrong target revision, stop and inspect the
  backend publish-gate evidence builder.
- If Playwright cannot find `Test Bench`, confirm the React route hint in
  `validation.yml` is `/admin/app/test-bench`.
