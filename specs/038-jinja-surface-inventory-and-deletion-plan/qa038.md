# QA038: Jinja Surface Inventory And Deletion Plan

## Goal

Validate the Spec 038 Jinja surface inventory for the React UI2 migration.

This guide proves that the repository can scan, classify, expose, and render every known Jinja-related surface before any deletion work starts.

This guide also proves that the inventory is deletion-safe: no item is marked safe to delete, all paths are repo-relative, tenant-scoped output is filtered, redaction checks are enforced, and reviewer signoff remains required.

QA038 uses `AUTH_MODE=local_principal`, deterministic Acme and Globex tenants, fake local secret references, and the isolated database `multi_agent_platform_qa038`.

No command in this guide should contact real Auth0, Telegram, model providers, connector tools, production databases, production credential stores, or external side-effect systems.

## What This Guide Covers

- Local-only environment setup for Spec 038.
- React admin migration page access at `/admin/app/migration`.
- Backend JSON inventory route access at `/admin/app/migration/jinja-inventory.json`.
- Scanner evidence written to `specs/038-jinja-surface-inventory-and-deletion-plan/jinja_inventory.json`.
- Template, include, route, TemplateResponse, Jinja2Templates, helper, static asset, and docs-link discovery.
- Classification by planned removal specs 039 through 047.
- Blocker evidence for retained Jinja surfaces.
- Tenant-admin filtering for tenant-safe views.
- Cross-tenant denial for Acme users requesting Globex scope.
- Auth0-shaped principal coverage through dependency override tests.
- Redaction sweeps for unsafe markers, local absolute paths, raw prompt data, and unauthorized tenant labels.
- Focused backend tests, frontend tests, full quality gates, and Playwright smoke evidence.
